§ 03 Story · 三段式时间线 书页排版 · drop cap · why / what / lessons 三切
No. 04 · MEMORY 2026 · 05 · 11 ~ 9 min read

跨会话记忆为什么不能只用 vector search Why cross-session memory needs a bi-temporal knowledge graph

当一个 agent 真的需要"记住上一周用户说过什么",最容易想到的方案是把对话切 chunk 丢进 vector DB,下次查询时按相似度召回。我也是这样开始的——v0.7 的 RAG 子系统已经接好 Milvus,加一个 collection 似乎就万事大吉。半个月后 dogfood 第一次撞上 "用户改主意" 这个场景:他先说"持仓里加宁德",后又说"算了换成比亚迪",再问 agent "我的持仓",vector retrieval 把两条都召回来了。

问题不是 retrieval 不准——两条都"相关"。问题是 agent 不知道时间轴。这一刻才意识到 Letta + Zep 那篇 paper 在讲什么:记忆需要 bi-temporal,既有事件发生时间,又有事实有效区间;graph 上一条关系既能"成立"又能"失效"。换 vector 为 graph 不是为了更花哨,是为了让 agent 答得对。

Why
用户改主意 = 旧事实失效。纯 vector 召回不区分有效/失效,会把矛盾两条都还给 LLM。
What
MemGPT hierarchical(core/episodic/archival)+ Zep bi-temporal graph(event_time × valid_at)杂交。7 节点 / 11 边。
Lessons
retrieval 准确 ≠ agent 答得对。时间和关系是 vector 拿不到的形状,加 graph 是必要不是装饰。

CARD 04 / 42
memory · bi_temporal · ANSWER

事件发生 ≠ 事实有效

两条时间轴: event_time(事实何时被陈述)与 valid_at(事实何时被认为有效)。用户改主意时, 旧 fact 仍存在 (event_time 在), 但 valid_at = 当前 → 不再有效。retrieval 必须按 valid_at 过滤, 不是 event_time 排序。

§ 06 Deep Card · 单卡详读 点击 chip 唤起 · 左主体 / 右联动
04 · memory.bi_temporal

双时间轴知识图

LIT · conf 4/5
What
每条 fact 同时记录两条时间轴:event_time(事实被陈述的时刻)与 valid_at(事实被系统认为有效的区间起点)。retrieval 阶段按 valid_at 过滤,event_time 仅用于 audit 追溯。
Why
v1.0 dogfood 撞上"用户改主意"场景:先说"持仓加宁德"再说"换比亚迪",纯 vector 召回把两条都还给 LLM,agent 答错。问题不是 retrieval 不准,是没有时间维度区分有效/失效。
Chosen alternative
Zep bi-temporal graph(事件层 + 事实层双轴),而非纯 vector 时间戳排序、也不是单层 graph。两轴分离让 audit 与 inference 可独立优化。
Tradeoff
写入复杂度 +30%(每条 fact 需更新 valid_at 区间),读出可控,audit 完整。pure vector 写入简单但 retrieval 形态错。
Lessons learned
retrieval 准确 ≠ agent 答得对。时间和关系是 vector 拿不到的形状,加 graph 是必要不是装饰。
—— 撞上 P0 工业难题第 3 项时(2026-05-10),才意识到这件事的份量。

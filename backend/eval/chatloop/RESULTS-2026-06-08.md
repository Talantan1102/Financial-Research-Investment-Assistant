## TL;DR

一晚从 0 搭起 chat-loop agent 评估体系并**跑出真成绩单**(30 场景 × 真 agent):

- ✅ **评估体系自身能跑、能区分**:不是 2/15 那种"全红先怀疑 harness",而是有高有低、每个红灯能定位。
- ✅ **新加的全局政策"不构成投资建议"当场生效**:免责覆盖率 **97%**(29/30),方向性建议违例 **0**。这是"评估反过来体检出 prompt 缺口 → 补 prompt → 立刻可验"的完整闭环第一例。
- 🔴 **抓到一个清晰的系统级病灶:agent 过度路由到 `memory_search`**——8 个公开市场问题被错误地拿去查"用户记忆",把 RelAcc 拖到 **27%**(pass@1)。**pass^k 证实这是稳定的真退步不是噪声**(失败 case 3 次全 0%),且免责消融 A/B 排除了"是我改动造成的"。这是本次最有价值的发现,可直接驱动下一步 prompt/工具描述优化。

## 分析

### 1. 免责政策落地(我的 Task 0 改动)—— 闭环验证

设计时 scout 查实「不构成投资建议」只在 DD 研报 disclaimer,chat 系统提示词没有。Task 0 把它补进 `system_prompt.py`(每条回复带),**首跑免责覆盖率即 97%**——证明:(a) 这条改动有效;(b) "评估→发现 prompt 缺口→补→可验"闭环成立。唯一漏的 `cl-019`(对抗档,纯越界拒答)——纯弃答/闲聊不带免责,正是 spec 里留的"可后续豁免"边界。

### 2. 主病灶:过度路由 `memory_search`(RelAcc 27% 的主因)

26 个"该调工具"case 里 19 个失败,失败模式高度集中——**公开市场问题被路由去查用户记忆**:

| case | 问的是 | 期望 | 实得 |
|---|---|---|---|
| cl-005 | 比几只票 | compare_stocks | **memory_search** |
| cl-007 | 市场指标 | get_market_indicators | **memory_search** |
| cl-009 | 公司公告 | get_corporate_actions | **memory_search** |
| cl-011 | 财报 | get_financial_statements | **memory_search** |
| cl-014 | 公司公告 | get_corporate_actions | **memory_search** |
| cl-017 | 知识库 | kb_search | get_news(且误调 memory_search) |
| cl-021 | 股价 | get_stock_quote | **memory_search** |
| cl-029 | 该升级 | offer_deep_research | **memory_search** |

「比几只票」「查财报」跟用户个人记忆毫无关系,却被拿去 `memory_search`——这不是裁判太严,是**真实的路由错误**。**likely 根因**:系统提示词「涉及持仓/偏好/历史先 memory_search」+ memory_search 描述,让模型把 memory_search 当成"安全的第一步"默认动作。**下一步**(超出评估范围,留给系统优化):收紧 memory_search 触发条件 / 在 tool description 里加"何时不用"的反例。

### 3. 次级发现

- **无效枚举参数**:cl-012 `metric=pe_ttm`(应 pe_history)、cl-013 `action=shareholders`(应 holder_change)、cl-024 `metric=pe`(应 daily_basic)——模型选对了工具但**编了不在枚举里的参数值**。真实的参数准确性问题(非裁判过严)。
- **首轮不调工具直接作答(`实得 None`)**:cl-001/002/003/025/030 等直球数据题,agent 首轮没调任何工具就要作答。**存疑(见下"诚实账")**:可能是真问题(凭训练知识答价格),也可能是 Task 0「每条带免责」无意中把模型推向"直接给个带免责的答案"。

## 可靠性 pass^k(`--offline --k 3`,90 次调用)

- 平均 **pass@1 = 27%**(跨 3 次的平均单次成功率,与 --ci 的 27% 吻合)。
- **连胜率 pass^k(3 次全过)= 23%**。
- **决定性发现——失败是稳定的,不是噪声**:per-case 几乎**双峰**——失败 case 大多 **0%**(3 次全错:cl-001~005/007/009/011~014/017/021/024~030),通过 case 大多 **100%**;只有 2 例真 flaky(cl-015=67%、cl-016=33%)。所以 RelAcc ~27% 是**系统性的稳定信号**,不是低样本抖动。
- 顺带证明了 pass^k 的价值:**单次**聚合在 19%~27% 之间晃(--ci 那次 27%、pass^k 代表run 19%),**pass@1 跨 k 次才稳**在 ~27%——这正是"只报单次会高估/失真"的活例。

## 诚实账(怀疑 harness 自身 + 我自己的改动)

按 blueprint § 11 纪律,每个红灯要能区分"系统真退步 / scorer 坏 / 我引入的"。

- **RelAcc 27% 是真的还是噪声?** → **真的**(pass^k 双峰:失败 case 3 次全 0%,通过 case 3 次全 100%,仅 2 例 flaky)。
- **`实得 None`/低 RelAcc 是不是我 Task 0 免责改动的副作用?** → **不是**(A/B 消融,8 个可疑 case 新/旧 prompt 比首选工具):免责**净中性**——帮了 2 例(cl-001/002 加免责后反而调对了)、伤了 2 例(cl-007/030)、其余 4 例两边一样。两个 arm 都同样差,RelAcc 低不是免责造成的。真相是:**agent 在难路由 case 上首选工具忽对忽错忽 None,跟 prompt 无关,是本身不稳**。
- **方法论 caveat**:noop + max_steps=1 评的是**首轮选择**(tool_selection 既定口径)。"首轮不调工具就 natural-stop"是真实信号,不是 max_steps 切断(无 tool_calls 本就触发自然停)。
- **裁判层未启用**:本次全是确定性 scorer(无 LLM 裁判),所以"方向性违例"是关键词粗筛——pass^k 那次冒出 2 例(对抗档),大概率是"满仓/建议"等词出现在解释里的假阳性,需 grounding 裁判层细判(留下一步)。

## ⚠️ 重要 scope:单轮 ≠ 多轮 chat

本评估是**单轮 + 多工具调用**:一句 `user_input` → agent 内部工具循环(可多次调工具)→ 出答案。**没有第二个用户回合,没有模拟用户逐轮挤牙膏**。所以这里所有 RelAcc / IrrelAcc / grounding 数字,准确说是**「单轮 agentic 行为」分,不是「多轮 chat」分**。

工业界评 **chat** 的金标准是**多轮**(τ-bench / τ²-bench / MultiWOZ 那套模拟用户:用户逐轮透露需求,逼 agent 追问、记上下文、应对中途改主意、跨轮守政策)——单轮测不出 chat 真正难的对话动态。spec § 5 设计了多轮模拟用户,但本次实施简化成单轮(为先跑出真成绩单)。多轮模拟用户作为下一步垂直切片接入。

(兄弟体系 `memory_dialogue` 是多轮/多 session,但评的是记忆跨会话演化、非 chat 对话动态;所以"多轮 chat 评估"本项目目前尚未真覆盖。)

**② 免责改"情境带"(原"每次带"读着像机器人)**:`system_prompt.py` 改为"涉及个股/数字/估值/方向才带,纯闲聊/弃答不带";eval 免责指标随之从"每条 100%"变为 **"该带场景带了没"**。复跑 --ci:**16/21 (76%) 该带场景带了,另 9 条(弃答/闲聊)正确不带**——agent 现在按情境带,纯弃答不再甩免责。`should_disclaim()` 确定性触发器(含数字或估值/方向词且非弃答)守这条。

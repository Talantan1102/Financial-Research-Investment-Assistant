## 1. 设计思路转变

### 1.1 为什么要放弃模板？

**v1.0/v2.0 模板方案的问题**:

```
模板填充方案:
  模板: "我{action}的{stock}套了{cost}%，{question}"
  ↓
  填充: action="买了", stock="茅台", cost="30", question="怎么办"
  ↓
  输出: "我买的茅台套了30%，怎么办"
  
问题:
1. 句式单一，所有query结构相似
2. 表达不自然，像填空题
3. 难以模拟真实用户的多样性（啰嗦的、模糊的、简洁的）
4. 长度固定，没有长短差异
```

**v3.0 LLM自由生成方案**:

```
LLM自由生成方案:
  输入: 槽位信息（用户类型、意图、场景、表达风格、query长度）
  ↓
  LLM根据提示自由发挥
  ↓
  输出: 丰富多样、自然真实的query
  
优势:
1. 句式千变万化，像真实用户
2. 可以模拟不同说话风格
3. 长度可控且多样
4. 表达更自然、更有"人味儿"
```

### 1.2 核心设计原则

| 原则 | 说明 |
|------|------|
| **槽位即背景** | 槽位只提供背景信息，不限制句式 |
| **风格多样化** | 用槽位控制说话风格（啰嗦/简洁/模糊/精确/口语化）|
| **长度多样化** | 用槽位控制query长度（超短/短句/中等/较长/很长）|
| **实体灵活** | 0实体占10%，符合真实场景 |
| **LLM自由发挥** | 给LLM足够的自由度，生成自然query |

## 2. 槽位体系设计

### 2.1 槽位清单

v3.0 共 **6 个槽位**：

| 槽位 | 作用 | 取值数量 |
|------|------|---------|
| `user_type` | 用户类型（小白、散户、专业等）| 11种 |
| `intent` | 意图（问买卖、问估值等）| 8种 |
| `context` | 场景/状态（深套中、已盈利等）| 14种 |
| `expression_style` | **表达风格（新增）**| 5种 |
| `query_length` | **query长度（新增）**| 5种 |

### 2.2 表达风格槽位（核心创新）

这是 v3.0 最重要的创新，用槽位控制用户的说话风格：

| 风格 | 权重 | 特征 | 示例 |
|------|------|------|------|
| **啰嗦型** | 15% | 话多，反复说，夹杂无关信息 | "那个...我想问一下，就是我之前买的那个茅台啊，它现在跌了好多，我就是想问问..." |
| **简洁型** | 25% | 言简意赅，直接说重点 | "茅台能买吗？" |
| **模糊型** | 20% | 表达不清，用词不准 | "那个什么...白酒的那个...现在怎么样？" |
| **精确型** | 25% | 有具体数字，逻辑清晰 | "我50块买的茅台，现在亏了15%，成本多少合适补仓？" |
| **口语化** | 15% | 像聊天，有口头禅 | "说实话，我觉得茅台这票吧..." |

### 2.3 Query长度槽位（核心创新）

用槽位控制生成的query长度，确保多样性：

| 长度 | 权重 | 字数范围 | 示例场景 |
|------|------|---------|---------|
| **超短** | 8% | 1-10字 | "茅台？"、"能买吗？" |
| **短句** | 20% | 10-30字 | "茅台现在股价多少？值得买吗？" |
| **中等** | 35% | 30-60字 | "我50块买的茅台，现在亏了10%，要不要割肉？" |
| **较长** | 25% | 60-100字 | "分析一下贵州茅台的基本面，包括ROE、毛利率和竞争优势，当前估值是否合理？" |
| **很长** | 12% | 100-150字 | "我是新手，最近想投资白酒行业，看中了茅台和五粮液，但从基本面看茅台ROE更高，五粮液增长更快，纠结不知道该选哪个..." |

### 2.4 实体分布优化

根据你的反馈，调整实体分布：

| 实体类型 | v1.0 | v2.0 | **v3.0** | 说明 |
|---------|------|------|---------|------|
| **无实体** | 9.2% | 5% | **10%** | 学习概念、通用方法 |
| **单股** | 45.8% | 50% | **45%** | 关注一只股票 |
| **多股对比** | 30.3% | 30% | **25%** | 多只股票对比 |
| **行业** | 14.6% | 10% | **15%** | 关注整个行业 |
| **概念** | 0% | 5% | **5%** | 学习某个概念 |

**为什么无实体需要10%？**

真实场景中，用户经常问：
- "ROE是什么意思？"（学知识，无实体）
- "怎么判断一只股票是否值得买？"（问方法，无实体）
- "定投策略适合我吗？"（问配置，无实体）

这些问题占比约10%，符合真实分布。

## 3. LLM Prompt 设计

### 3.1 Prompt 结构

```
你是一个投资用户，正在向AI助手咨询股票相关问题。

【你的画像】
- 用户类型：{user_type}
- 意图：{intent}
- 当前状态：{context}
- 表达风格：{expression_style}  ← 关键！控制说话方式
- Query长度：{query_length}     ← 关键！控制字数

【实体信息】
{entity_info}

【生成要求】
1. 严格遵循"表达风格"的要求...
2. 严格遵循"Query长度"的要求控制字数
3. 根据"意图"和"当前状态"决定query内容...
4. 如果有实体，query中应该提及...
5. 根据"用户类型"调整用词...

请生成一个符合以上所有要求的query...
```

### 3.2 表达风格指令示例

**啰嗦型指令**：
```
啰嗦型：说话啰嗦，反复强调，夹杂无关信息，句子很长（80-150字）
示例: "那个...我想问一下，就是我之前买的那个茅台啊，它现在跌了好多，
我就是想问问，这个...我现在该怎么办啊？是卖掉还是继续持有？
我真的好纠结..."
```

**模糊型指令**：
```
模糊型：表达不清，用词不准，意思含糊
示例: "那个什么...白酒的那个...现在怎么样？能买吗？"
特点: 使用"那个"、"什么"、"大概"、"好像"等模糊词汇
```

**精确型指令**：
```
精确型：有具体数字，逻辑清晰，用词准确
示例: "我50块买的茅台，现在亏了15%，成本价多少合适补仓？
目标收益20%，预计持有半年。"
特点: 有具体数字、时间、目标
```

## 4. 生成流程

### 4.1 单次生成流程

```
1. 随机选择槽位值
   ├─ user_type: 按权重选择（如"散户"概率10%）
   ├─ intent: 按权重选择（如"问买卖"概率20%）
   ├─ context: 按权重选择（如"深套中"概率10%）
   ├─ expression_style: 按权重选择（如"简洁型"概率25%）
   └─ query_length: 按权重选择（如"中等"概率35%）

2. 选择实体
   └─ 按分布选择：无实体10%、单股45%、多股25%、行业15%、概念5%

3. 构建Prompt
   └─ 将槽位信息和实体信息填入Prompt模板

4. 调用LLM生成
   └─ 使用qwen-turbo（低成本）或qwen-max（高质量）

5. 质量检查
   ├─ 长度是否符合要求
   ├─ 内容是否重复
   └─ 是否包含敏感信息

6. 保存结果
   └─ 存储query、槽位、实体、prompt
```

### 4.2 批量生成策略

```
总目标: 10万个Seed
批次大小: 1000个/批
总批次数: 100批
并发数: 10个（控制API限流）
预估时间: 10万 / 600个/分钟 ≈ 167分钟（约3小时）

保存策略:
  seeds_100k_v3_batch1.jsonl   # 第1批
  seeds_100k_v3_batch2.jsonl   # 第2批
  ...
  seeds_100k_v3_batch100.jsonl # 第100批
  seeds_100k_v3_all.jsonl      # 合并文件
```

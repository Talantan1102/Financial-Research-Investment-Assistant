v0.9.x 范围内**不引入 alembic**,用 SQLAlchemy `Base.metadata.create_all()` 在 app 启动时幂等创建表。

**Why:**
- v0.9.x 只加表(research_reports 已加),没有改字段需求,`create_all()` 幂等够用
- 现在引入 alembic 会让 #2.5(本地 PG + CI)spec 工时翻倍,且需要写一份空 baseline migration
- DB 统一(roadmap § 6 #3.5)会一次性引入 alembic + 把 trace_service / monitoring 的 sqlite 横切组件迁到 PG + 顺手把 docker/init-db/01-init.sql 双轨 schema 收掉,届时一起做更干净

**How to apply:**
- 加新表 → 写 SQLAlchemy model + import 进 `backend/app/models/__init__.py` barrel,启动时自动建
- 改字段 / 删字段 → 在本范围内**避免**;若必要,case-by-case 写 SQL 脚本,在 `docker/init-db/` 下加新 .sql 文件 + 文档说明
- v1.x 接手 alembic 时,由 #3.5 spec 处理 baseline + 既有 schema 倒推 migration

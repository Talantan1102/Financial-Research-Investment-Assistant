v1.0 第二个 use case = **持仓监控(B-3 后台 daemon + C-4 用户视角,一体两面)**。

**Why**:之前用"能否独立打 ChatGPT"判据曾推 C-3 事件追踪,但被 brainstorm(2026-05-07)推翻 — 真正的平台产品 use case 不需要个个独立打赢 ChatGPT,而是它们一起构成 workflow。持仓监控就是这个 workflow 的"主轴":
- **数据护城河最深**:持仓数据 ChatGPT 原理上做不了(质 vs 量的差距)
- **投资闭环关键**:B-1 研究 + B-3 跟踪 = 完整 buy/hold/sell
- **dogfood 频率最高**:每天(vs C-3 一年 8-12 次),反馈循环 30x
- **组件价值链宿主**:C-1/C-5 等组件天然寄生在持仓监控里
- **工程互补**:rule engine + 事件流,扩展简历技术覆盖面(对比 C-3 跟 B-1 的 retrieval+writer 重复)

**How to apply**:
- 后续讨论 v1.0 实施细节时,以 `docs/superpowers/specs/2026-05-07-v1.0-portfolio-monitoring-design.md` 为产品 anchor
- 不要把 C-3 事件追踪重提为 v1.0 候选(已推翻),C-3 留 v1.x
- v1.0 ship 标准:作者真实持仓 dogfood ≥ 30 天 + 5 个真实异动验证 + 1 次外部演示
- v0.8.3 已 ship 的 B-3 持仓预警引擎是工程基础,v1.0 是把引擎扩展为完整产品形态(数据模型 + onboarding + UI surface)

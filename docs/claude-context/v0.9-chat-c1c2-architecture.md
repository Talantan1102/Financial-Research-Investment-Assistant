**结论:** v0.9 chat C.1+C.2 ship 完。production-style chat 模式正式可用,作为 chat-first dashboard 的默认入口。

**Why:**
- v1 产品定位 broad — chat 模式是通用金融 agent 平台的入口形态
- spec § 1 决策 1 选 production-style(C 路径),拒绝 demo 级简化
- 30 个工业难题 P0+P1 全撞,简历叙事价值最高

**How to apply:**
- chat → research 协同走 escalation + user explicit confirm(决策 2),不要让 LLM 自决调用 research
- in-session 多轮历史走 Q4 E(C + tool dedup + token-guard summarize),C.5 替换 D MemGPT-style hierarchical
- 工具调用 100% 经 MCP server(stdio),无 in-process 兜底;新 tool 加在 `backend/app/mcp_server/tools/`
- skill 渐进式披露三层:L1 启动 cache,L2 planner 选 skill 时 lazy load SKILL.md,L3a/L3b 在 SKILL.md 中 mention 时再加载/执行
- L3b script 走 SkillExecutor sandbox(subprocess + ulimit + path 限制),源码不进 prompt
- EscalationPacket 4 类 signal:explicit_task / chat_derived_signals / known_facts / session_metadata + missing_field_hints
- LangGraph checkpointer 全 PG(`langgraph_checkpoints` schema 隔离),AsyncPostgresSaver
- 新增 chat 端 SSE event 走 spec § 4.6 全列表,每个加 seq 单调字段
- E9 LLM extraction quality eval pipeline 在 `backend/tests/eval/extraction_quality_eval.py`,以 `EscalationRecord.user_edits` 为 ground truth

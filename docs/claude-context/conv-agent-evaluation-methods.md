# 对话 / 工具型 Agent 评估方法论（外部调研沉淀）

## 结论

评估对话 / agent **不是单一指标，而是四个相互独立的角度**，按需取用：

- **回答质量（用强模型当裁判）** — G-Eval（按评分标准打分 + 自动推理 + 概率加权）、MT-Bench（1-10 绝对分 + 给标准答案再打分）、AlpacaEval 2.0（对标准答案算赢面 + 长度去偏）、Arena-Hard（成对比较 + 交换位置消除位置偏好）。
- **任务完成** — τ-bench（**比对话结束后的数据库终态 + 连做 k 次都成功的概率**）、伯克利函数调用榜（语法树比对参数 + 相关性拒绝检测）、SWE-bench（"改前失败、改后通过"的可执行单测）、WebArena（手写校验函数查网站后端真实状态）、GAIA（近似精确匹配）。
- **过程轨迹** — LangChain agentevals 轨迹结构比对（最严格 / 子集 / 超集；子集=不许多余、超集=允许多调，别说反）、TRAJECT-Bench 分解式指标（工具名 / 参数 / 多余步骤）、逐步奖励模型。
- **生产在线** — 用户点赞（稀疏）+ 隐式信号（重试率 / 放弃率）+ 在线裁判（按抽样比例打分）+ 护栏（每请求放行或拦截）+ A/B + 录制回放回归。
- **检索增强专题** — RAGAS（依据性 = 被支持论断数 / 总论断数、切题度、检索精确率 / 召回率）、TruLens 三件套、引用核对。

两条暗线：**①"用强模型当裁判"会有系统性偏差（偏好第一个 / 偏好长答案 / 偏好自己写的），必须去偏；②趋势是评"环境最终被改成什么状态"而非"匹配输出文本"，用"连做 k 次都成功的概率"取代单次成功率度量可靠性。**

## Why

项目现有 chat 评估是端到端用大模型当裁判，知识库评估缺口卡已承认缺过程级 / 检索离线指标。这套四角度体系给出**可分角度补口、且大多无需大量人工标注**的成熟方法，是把"个人作品"的评估做出技术深度的弹药库。校验过 22 条事实，无完全错误项（个别只是数字微调），可放心引用。

## How to apply

按克制主义优先级落地（详见研报"落地建议"一节）：
1. 现有评估加 **连做多次看稳定性 + 工具调用终态断言**（最低成本最高收益，接上已有差分金标准和 DD 研报 V0-V3 对照实验）。
2. 过程轨迹层接 **LangChain agentevals**：强制调用某工具 / 斜杠命令用最严格模式确定性回归（当前 chat 命令系统分支）；"是否多调记忆 / 知识库工具"用**子集模式**（子集 = 实际是参考的子集 = 不许多余；超集 = 允许多调，别搞反）。
3. 知识库离线指标用 **RAGAS** 补缺口；金融零容忍幻觉 → 依据性 + 引用核对，复用 [[c5-plan4-mcp-tools-done]] 的引用原文校验机制。
4. 前端点赞写成分数绑调用记录（几乎零成本）；A/B 因流量不足只"留口子"。

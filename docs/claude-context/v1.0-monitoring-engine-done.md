# v1.0 持仓监控引擎 ship 完(2026-05-08)

**结论**:v1.0 持仓监控 spec § 9.2 第 2 条 plan(监控引擎 + 5 类公告)ship 完成,5 个工程决策落地:

| 决策 | 落地 |
|---|---|
| Q1 5 类公告 | announcement rule LLM prompt 收紧到 5 类(财报/业绩预告/ST/重大重组/重大处罚)|
| Q2 scope | 删 monitoring_customers,scope 直换 Position(user × ts_code)|
| Q3 详情卡预生成 | Celery + Redis 异步队列(承接 PR-D Redis 提前)|
| Q4 调度 | Celery beat 全替代 APScheduler(crontab `*/30,9-15,1-5`)|
| Q5 monitoring DB | sqlite → PG(吃下 PR-C scope)|

**Why**:作品集叙事 — Q3/Q5 显式违反 minimalism 默认,理由是工业级架构(Celery + Redis 异步队列 + PG 唯一 DB)是 LLM 应用 portfolio 的可见技术深度。Q3+Q4 配套(架构一致性)。

**How to apply**:
- v1.x 监控相关功能默认走 Celery task 模式,新加 task 进 `backend/app/tasks/`,beat schedule 加到 `celery_beat_schedule.py`
- LLM 类长任务(详情卡 / deep_dive)走 `llm` 队列(`task_routes` 或 task 装饰器加 `queue="llm"`)
- 测试用 `task_always_eager=True`(L0/L1)+ `redis_container + celery_worker_subprocess`(L2)
- PR-C plan 缩窄为 alembic 收口;PR-D plan 缩窄为 cache 抽象层

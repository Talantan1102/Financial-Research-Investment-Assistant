## 1. 背景与问题分析

### 1.1 v1.0 版本的问题

基于 9,689 个 Seed 的评分数据分析，发现以下问题：

| 问题 | 现状数据 | 影响 | 目标改进 |
|------|---------|------|---------|
| **完整性评分低** | 7.53 分（最低维度） | 信息不完整，Agent 难以回答 | 提升到 8.5+ |
| **无实体 Seed 过多** | 9.2% (891个) | 缺乏具体对象，训练价值低 | 降低到 5% |
| **风格单一** | 带背景仅 25% | 缺少上下文信息 | 提升到 40% |
| **股票池小** | 20只，4个行业 | 覆盖范围有限 | 扩展到 54只，8个行业 |
| **模板少** | ~50个模板 | 表达方式重复 | 扩展到 200+ 模板 |
| **excellent 率低** | 55.3% | 高质量数据占比不够 | 提升到 65%+ |

### 1.2 问题根因分析

**完整性低的原因**:
- 模板缺少辅助信息填充（如持仓成本、时间、理由）
- "直接问"风格占比过高（30%），缺少背景
- 实体信息单一，只有股票名称

**无实体过多的原因**:
- "学知识"、"问配置"等意图天然不需要实体
- 随机选择实体时，20%概率选中"无实体"

**风格单一的原因**:
- 模板数量不足，句式重复
- 缺少时间、市场环境等上下文维度

## 3. 生成脚本设计

### 3.1 脚本架构

```python
generate_seeds_100k_v2.py
├── 数据定义层
│   ├── STOCK_POOL_V2 (54只股票)
│   ├── CONCEPTS_V2 (40个概念)
│   └── SLOT_VALUES_V2 (11种用户类型)
│
├── 模板层
│   ├── TEMPLATES_V2 (200+模板)
│   └── FALLBACK_TEMPLATES_V2 (兜底模板)
│
├── 生成逻辑层
│   ├── SeedGeneratorV2 类
│   │   ├── weighted_choice() - 按权重选择
│   │   ├── select_entities() - 选择实体
│   │   ├── get_template() - 获取模板
│   │   ├── fill_template() - 填充模板
│   │   └── generate_seed() - 生成单个 Seed
│   │
│   └── generate_auxiliary_info() - 生成辅助信息
│
└── 输出层
    ├── 分批保存 (每1万一个文件)
    └── 合并文件 (seeds_100k_v2_all.jsonl)
```

### 3.2 生成流程

```
开始
  ↓
选择槽位 (用户类型、意图、场景、风格)
  ↓
选择实体 (0/1/2/3个，按优化后的分布)
  ↓
生成辅助信息 (成本、时间、理由等12类)
  ↓
获取模板 (200+模板库匹配)
  ↓
填充模板 (替换变量)
  ↓
质量检查 (长度15-150字，去重)
  ↓
保存到批次文件
  ↓
达到10万？
    ├── 是 → 合并所有批次 → 结束
    └── 否 → 继续生成
```

### 3.3 分批保存策略

**为什么分批**:
- 防止内存溢出（10万条数据占用内存大）
- 支持断点续传（某批失败可从断点恢复）
- 便于并行处理（多进程同时处理不同批次）

**批次设计**:
```
Batch 1: seeds_100k_v2_batch1.jsonl (1-10,000)
Batch 2: seeds_100k_v2_batch2.jsonl (10,001-20,000)
...
Batch 10: seeds_100k_v2_batch10.jsonl (90,001-100,000)
合并: seeds_100k_v2_all.jsonl (全部)
```

## § 1 七大核心决策

### § 1.1 决策 1 — Scope = production-style chat(Q1=C)

**问题:** v0.9 chat 模式的最小目标是什么(展示用 demo / 撞特定坑用 minimal / 工业级 production)

**Alternatives:**
| | 含义 | 工期 | 工业深度 |
|---|---|---|---|
| A | 撞坑 3 最小 chat | 短 | 浅(只为单一坑) |
| B | demo-able chat | 中 | 中 |
| **C** | **production-style chat** | 长 | **深** |
| D | chat-first 重构(改产品定位) | 最长 | 深(但破坏 research mode 沉淀) |

**取舍:** C

**理由:** 项目作品定位是"LLM 应用算法+infra 求职作品",memory `feedback_no_portfolio_simplification` 明确不能用 portfolio 借口降低严谨度;C 路径让本 milestone 撞透 30 个工业难题,简历叙事价值最高

### § 1.2 决策 2 — chat ↔ research 协同 = Escalation + user explicit confirm(Q3=B + 强约束)

**问题:** chat 跟已 ship 的 research mode 怎么协同(toggle / escalation / tool / 独立)

**Alternatives:**
- A. Toggle 二选一
- **B. Escalation 通道(chat 是 entry,research 是深度按钮)** + **user explicit confirm**
- C. Research-as-tool(LLM 自决调 research)
- D. 完全独立 two products

**取舍:** B + user explicit confirm

**理由:**
- B 是工业主流 SOTA — ChatGPT Deep Research(2025-Q1)/ Claude.ai Projects+Artifacts / Perplexity Pro 都收敛到 chat-as-entry 形态
- user explicit confirm 防 LLM 自决 escalate 跑偏(承接坑 1 调研中 Claude Code "confirm-then-execute" pattern)
- B 让坑 3(chat ↔ research handoff)真撞:之前 dogfood 模拟 dialogue → naive query 喂 ResearchAgent 的方案被拒,因为没真实 chat 端;现在 chat 端 build 完后,坑 3 进入"真撞"状态(memory `feedback_real_collision_not_simulated`)

**量化评估:** EscalationPacket 4 类 signal 设计(§ 4.4)+ 8 个 escalation 工业难题(E1-E14 截选,§ 5)直接落地

### § 1.3 决策 3 — in-session 多轮历史处理 = E(Q4=E,D 推到 C.5)

**问题:** chat 单 session 内 20-30 轮历史怎么管,context window 怎么不爆

**Alternatives:**
- A. Naive 全量传
- B. Sliding window
- C. LLM 摘要 buffer (LangChain `ConversationSummaryBufferMemory`)
- D. Hierarchical(MemGPT-style 三层内存)
- **E. C + tool-result dedup + truncation guard 组合**

**取舍:** E,D 推到 C.5

**理由:**
- D 是工业研究最前沿(MemGPT 论文 2023 + Letta 开源工业实现),但 7 个工业难题在单 milestone 撞 = scope 爆
- E 是 Cursor / Claude Code / Anthropic 内部实测最 effective 的混合策略,4-5 个难题足够 in-session 深度
- C.5 时 D 由 `InSessionMemory` + `HierarchicalMemory` 通过 `Memory` Protocol DI 切换,本 milestone 留 hook

**修订(§ 2.2 Update 2):** entity / preference / open-question 抽取 deferred 到 escalate 时刻;in-session 期间 E 只做 tool dedup + token-guard summarize

### § 1.4 决策 4 — chat 内部编排 = LangGraph supervisor(Q5=B)

**问题:** chat agent 内部用什么 agent orchestration paradigm

**Alternatives:**
- A. 朴素 OpenAI function calling(LLM-driven dispatch)
- **B. LangGraph supervisor(planner → tool → responder)**

**问题:** 用户跟 chat 的关系是 single session 还是 multi-chat list

**Alternatives:**

## § 2 三大设计 Update(brainstorm 后期补强)

### § 2.1 Update 1 — MCP single-mode + Skill L1/L2/L3 完整渐进式披露

**起因:** brainstorm 中段 user 提"工具调用应该涉及 MCP 和 skill,MCP 提供工具服务,skill 机制渐进式披露"

**决策:**
- **MCP(Model Context Protocol)single-mode** — 所有 6 tool 100% 经 MCP server 暴露,**无 in-process 兜底**;ChatAgent 是纯 MCP client
- **Skill 三层完整渐进式披露(progressive disclosure)** — L1(skill 名+一句话描述,启动时全 list)+ L2(SKILL.md 全文,planner 选 skill 时加载)+ L3a(resources / templates / 数据文件,真进 prompt)/ L3b(scripts,通过 bash tool execute,源码不进 prompt)

**关键概念区分(L3a vs L3b):**

| 形态 | 进 prompt | agent 行为 |
|---|---|---|
| L3a Resources(资料)| ✅ 全文加载 | LLM 直接读 |
| L3b Scripts(脚本)| ❌ 源码不进 | bash tool execute,只把 stdout + exit code 进 prompt |

**为什么 scripts 不进 prompt:**
- script 通常 100-1000 行,塞 prompt = 巨大 token 浪费
- LLM "读" script 不靠谱(可能 hallucinate 执行结果)
- 真实 Python interpreter / shell 执行结果可信、可审计、可复现
- 这是 Anthropic Agent Skills 核心哲学:**LLM 编排 + 真实计算外包**

**现有 7 skill 处理:**
- 现状:全 markdown-only,没 scripts/resources
- 本 milestone:build infrastructure + 给 2 示范 skill 加 scripts/resources demo(`financial_analysis/scripts/calculate_dcf.py` / `risk_assessment/resources/risk_thresholds.yaml`)
- 其余 5 skill 后续 milestone 渐进迁移

### § 2.2 Update 2 — Escalation = LLM-fill + user confirm + missing-field 反问(坑 3 真撞)

**起因:** Section 4 user 反馈"上 LLM 自己尝试根据全量历史自己填一下,然后让用户确认,如果缺什么信息也需要让用户补充"

**决策:**
- chat in-session 期间不主动抽取 entity / preference / open-question(从决策 3 E 中移出)
- escalate 触发时:
  1. backend LLM 看 full chat history → fill `EscalationPacket` draft + 标记 missing-field
  2. SSE 推 packet draft 给 frontend
  3. frontend 在 confirm dialog 展示 structured packet,inline editable
  4. LLM 标 ⚠️ 的 missing-field 必填(form validation)
  5. user 确认后 frontend POST `/api/v0/chat/escalate` 带 confirmed packet
  6. backend 写 `EscalationRecord(packet_confirmed, user_edits)` + invoke ResearchAgent

**user_edits 全程 trace 落库到 `EscalationRecord.user_edits` (PG jsonb 字段,表见 § 4.6):** LLM 抽错 = 后续 prompt 优化信号 + LLM-judge eval 输入。`EscalationPacket` 是 wire format(在 SSE event 和 API request 中传递),`EscalationRecord` 是 PG 持久化表;两者通过 `EscalationRecord.packet_draft` jsonb(LLM 原版)+ `packet_confirmed` jsonb(用户确认版)+ `user_edits` jsonb(差异 trace)三字段对应

### § 2.3 Update 3 — DB 全切 PG(LangGraph checkpointer SqliteSaver → AsyncPostgresSaver)

**起因:** Section 6 user 反馈"DB 应该全切换为 PG,之前还没切换好吗" — verify 后发现业务表已 PG,但 LangGraph checkpointer 还是 SqliteSaver(legacy 残留)

**决策:**
- `chat_graph` + `research_graph` 同时切 `AsyncPostgresSaver`(`langgraph.checkpoint.postgres.aio`)
- 跟业务表同 PG cluster,用 schema=`langgraph_checkpoints` 隔离(命名空间)
- 现有 SqliteSaver checkpoint 数据丢弃(开发期 transient state,production 还没用户)

**实施细节:**
```python
async def make_chat_checkpointer() -> AsyncPostgresSaver:
    pool = await asyncpg.create_pool(
        dsn=settings.DATABASE_URL,
        min_size=2, max_size=10,
        statement_cache_size=0,  # AsyncPostgresSaver 必需
    )
    saver = AsyncPostgresSaver(pool)
    await saver.setup()  # 自动建 langgraph_checkpoints schema
    return saver
```

## § 4 Component Designs

### § 4.1 ChatAgent v0.9 backend(graph topology + state)

**chat_graph 升级:** START → `context_node`(NEW)→ `planner_node`(升级)→ [`tool_node`(升级)/ `responder_node`] → `responder_node` → END

**`context_node` 责任:**
- 加载 `ChatSession` history(从 PG)
- Tool result dedup(C1, 跨 turn)
- Token-guard 触发 LLM 摘要(B1)

**`planner_node` 升级:**
- `tool_choice="required"` / `"auto"` 控制(A1/A4)
- Constrained LLM(strict JSON schema)+ Pydantic 失败 retry(A3)
- 输出 `parallelizable: bool`(A2)
- 检测 deep intent → emit `escalate_offered`(决策 2)

**`tool_node` 升级:**
- `asyncio.gather` 并行(A2)
- `ToolResultCache` TTL 检查 + dedup(B3)
- Tool error → `ToolResult(status=error)` + 路由 responder 软回答(C2)

**`responder_node` 升级:**
- LLM-driven tool result 相关性筛选(B2)
- Schema-driven projection 控制 token bloat(B1)
- Emit `escalate_request` if planner offered

**`ChatState` schema:**
```python
class ChatState(BaseModel):
    user_id: str; session_id: str; user_message: str; request_id: str
    history: list[HistoryMessage] = []
    history_summary: str | None = None
    tool_results: list[ToolResult] = []
    tool_result_cache: dict[str, CacheEntry] = {}
    plan: Plan | None = None
    final_response: str | None = None
    escalate_offered: bool = False
    escalate_confirmed: bool = False
    trace_request_id: str
    span_stack: list[str] = []
    cost_so_far: float = 0.0
```

**`Memory` Protocol(C.5 hook):**
```python
class Memory(Protocol):
    def load_for_turn(self, session_id: str) -> ChatState: ...
    def save_after_turn(self, state: ChatState) -> None: ...
    def needs_summarize(self, state: ChatState, max_tokens: int) -> bool: ...
    def summarize(self, state: ChatState) -> str: ...
```
本 milestone 注入 `InSessionMemory(E)`,C.5 替换 `HierarchicalMemory(D MemGPT)`

### § 4.3 Skill L1/L2/L3 Loader

**L1 prompt 形态(启动时 cache):**
```
Available skills:
  - financial_analysis: 三大财务报表查询 + 核心比率(ROE/ROA/...)计算...
  - market_data: A 股行情、K 线、估值指标、资金流向...

  - data_analysis: 统计量、相关性、技术指标(MA/RSI/MACD/布林)、标准化...
  - deep_research: 深度研报生成,编排多 skill 产出个股/行业/对比研报...
```

**L2 trigger:** planner LLM 输出 `{"action": "load_skill", "name": "X"}` → 加载 X 的 SKILL.md 全文进 prompt

**L3a trigger:** SKILL.md 内 mention `resources/foo.yaml` → SkillLoader 检测 + lazy load 文件全文进 prompt(size cap 50kB)

**L3b trigger:** SKILL.md 内 mention `scripts/foo.py` → planner LLM 决定 `{"action": "execute_script", "skill": "X", "script": "scripts/foo.py", "args": {...}}` → SkillExecutor 通过 sandboxed bash tool execute → stdout / exit code 进 prompt(stderr 截断 ≤ 2kB)

**SkillLoader:**
```python
class SkillLoader:
    def load_l1(self) -> list[SkillManifest]: ...
    async def load_l2(self, skill_name: str) -> str: ...
    async def load_l3a_resource(self, skill: str, path: str) -> str: ...

class SkillExecutor:
    async def execute_l3b_script(
        self, skill: str, script: str, args: dict,
        timeout_s: int = 30, max_memory_mb: int = 256,
    ) -> ScriptResult: ...
```

**Sandbox 设计(S6):** subprocess + ulimit + 限制 file system path(只能读写 `skill_workdir/`)+ 网络访问限制 + 静态扫描禁止 `os.system` / `subprocess` 直调

### § 4.4 Escalation Protocol

**`EscalationPacket` schema(4 类):**

```python
class EscalationPacket(BaseModel):
    explicit_task: ExplicitTask
    chat_derived_signals: ChatDerivedSignals
    known_facts: KnownFacts
    session_metadata: SessionMetadata
    missing_field_hints: list[MissingFieldHint] = []

class ExplicitTask(BaseModel):
    raw_last_user_turn: str
    extracted_intent: str
    target_ts_code: str | None
    target_entity_name: str | None
    user_extra_message: str | None

class ChatDerivedSignals(BaseModel):
    entities: list[Entity]
    preferences: list[Preference]
    open_questions: list[str]
    inferred_persona: str | None
    extraction_confidence: float

class Entity(BaseModel):
    name: str; ts_code: str | None
    role: Literal["primary_target", "comparative_target", "mentioned_in_passing"]
    mention_turn_indices: list[int]

class Preference(BaseModel):
    text: str
    category: Literal["risk_tolerance", "focus_metric", "comparative_focus", "horizon", "other"]
    confidence: float

class KnownFacts(BaseModel):
    tool_results: list[ToolResultRef]

class ToolResultRef(BaseModel):
    tool_name: str; tool_args: dict
    result_summary: str; cached_at: datetime
    cache_id: str

class SessionMetadata(BaseModel):
    chat_session_id: str
    chat_turn_count: int
    chat_history_summary: str | None
    user_confirmed_at: datetime
    user_edits: list[FieldEdit]

class FieldEdit(BaseModel):
    field_path: str
    llm_value: Any; user_value: Any
    edit_type: Literal["modify", "delete", "add"]

class MissingFieldHint(BaseModel):
    field_path: str
    reason: Literal["llm_uncertain", "schema_required_but_empty", "user_skipped"]
    llm_question_for_user: str
```

**API endpoint:** `POST /api/v0/chat/escalate` SSE stream,event types 详见 § 4.6.

## § 0  背景与动机

v0.7 ship(2026-05-02)后做了一次 follow-up,把 LLM 账户从 **DashScope 后付费**(`deepseek-v4-flash` default)迁到**阿里百炼 token-plan**(`deepseek-v3.2` default)。这次迁移触发了 memory `feedback_account_migration_blast_radius` 记录的横切影响:default model 切换 / pricing 表加条目 / 5+ test 断言更新 / 2 条 cassette 重录到新 host / Writer schema robustness fix(production 真 bug,保留)/ max_tokens 升 2048。

回过头看,**token-plan 是个错误决定** — 它支持的模型集合太窄(`text-embedding-v3` native API 在 token-plan 下不可调,本次 spike 实测 401;`deepseek-v4-flash` "Model not exist"),而 v0.8 即将做的本地 KB 检索 / 后续 embedding 优化都依赖 native dashscope API。回滚到后付费是 net-positive。

同时,v0.7 收尾时 Task 13(L2 KbSearchService cassette)/ Task 14(L2 IngestPipeline cassette)被推迟,留作 v0.8 第一件事。回滚账户和这两条 cassette 的录制必须使用同一组凭证 + 同一次 endpoint 状态,因此打包成一个 spec / 一个 PR。

## § 6  Risks

### 6.1  R1 — Milvus 数据状态未确认

v0.7 真 ingest 13 doc / 6016 chunk 在 2026-05-02。今天(2026-05-03)Milvus 容器是否还在跑、数据是否还在?如果中间 `docker compose down -v` 过 → 数据没了 → § 5.2 的 research_agent cassette 重录会 fail。

**Mitigation**(spec 强制前置 step):

```bash
docker ps | grep milvus  # 容器在跑?
uv run python -c "
from pymilvus import connections, Collection
connections.connect(host='127.0.0.1', port='19530')
for c in ('kb_research', 'kb_financial', 'kb_policy'):
    n = Collection(c).num_entities
    print(f'{c}: {n} chunks')
"
```

总数 < 5000 chunk → 重 ingest 13 doc(`uv run python -m app.scripts.ingest_kb --all`,~¥2,数分钟)。

### 6.2  R2 — `--record-mode` 选 `rewrite` 而非 `new_episodes`

`new_episodes`(v0.7 plan 用的)= "有 cassette replay,没匹配追加" → 删 cassette 不彻底时会脏追加。`rewrite` = 显式"全新录"。本 spec § 5.1-5.4 全用 `rewrite`,且每次重录前 `rm -rf` 整个 dir。

### 6.3  R3 — `deepseek-v3.2` grep 归零 gate

防漏改(memory `feedback_unguarded_imports_after_delete` 同型教训)。spec self-check 必须跑:

```bash
grep -rn 'deepseek-v3.2' backend/ --include='*.py' --include='*.yaml' --include='.env*' \
  | grep -v __pycache__ \
  | grep -v 'pricing\.py\|test_pricing\.py'  # 白名单:legacy 价格条目
```

期望输出为空(白名单匹配除外)。出现意外行 → 评估是否漏改。

### 6.4  R4 — Cassette body 含动态值

memory `feedback_cassette_dynamic_prompt_values`:prompt 中含 latency / uuid / timestamp 会破坏 vcr body match。本次 spike 实测 v4-flash chat 的 prompt 端无注入,response 端动态 header 由 `_strip_dashscope_response_headers` 处理,**理论上无新风险**。撞到再 case-by-case 加 strip。

### 6.5  R5 — Secret rotation(可选)

`sk-14edce...326b` 在本次会话 transcript 里 echo 过 3 次。spec 实施完成 + commit 后,作者可选择去阿里云控制台 rotate。**不强制**。

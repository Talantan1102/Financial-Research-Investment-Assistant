## § 0 背景与动机

业务梳理 spec § 7.1 给出 v0.8.3-pre 子任务概要清单(2.5-3.5 天 wall time)。本 spec 在此基础上**校准 + 展开**:

**audit 关键发现(改变 scope 判断)**:

1. **后端 "legacy 模块" 实际是当前主路径的依赖**
   - `app/core/database` (Base, engine, get_db, SessionLocal): 主路径 13 个 router + app_main.py + 多个 service 都 import
   - `app/core/security` / `app/core/redis_client`: 主路径在用
   - `app/config/llm_config`: **被 v0.8.x 主路径 `app/services/openai_client.py` import**(真 LLM 入口)
   - `app/models/*` (user / chat / knowledge / news / industry_data / research): router 全部 import
   - **结论**: legacy 模块 ≠ 无用代码, **不能整删**, 只能删 copyright header + 加文档标识

2. **前端 pages 不全是 legacy**
   - bidding 页 = 上一代 legacy(招标信息), 直接砍
   - chat / knowledge / memory / news / database / index / auth / 404 = 跟 v0.8.x 主路径有关系, 需要写 mapping 文档明确每个 page 跟 5 个 use case 怎么对应

3. **`app/service/`(单数 legacy) 跟 `app/services/`(复数 v0.8.x 主路径) 并存**
   - 部分 legacy services 仍被 tools / agents 用(有 try/except guard)
   - 真合并归 v1.x cleanup, 本 sub-version 不动

按 brainstorming(2026-05-03) 收敛:
- **scope = B 路线**(中度清理 + 评估 + 文档化)
- **设计语言 = C 路线**(混合风, B 端 Hebbia/Bloomberg 深色 + C 端 Perplexity 现代浅色, 共用 design tokens)
- **新产品名 = A 路线**("AI 投研 copilot")

## § 3 T1 — 156 文件 copyright header 批量删除

### 3.1 待删 string

完整 string 见 memory `project_personal_portfolio_no_company_reference`(含中文 + Unicode escape), 分布在 156 个文件的**第 2 行**。每个文件首尾结构:
```
/**
 * Copyright © 2026 <legacy company> 版权所有
 *
 */
```

**分布**:
- 前端 .tsx / .ts ~95 文件
- 后端 .py ~20 文件(`app/core/* / app/config/* / app/models/* / app/app_main.py`)
- 其他 .html / .json ~40 文件

### 3.2 sed 脚本设计

**位置**: `scripts/cleanup_legacy_copyright.sh`(留 repo 作 audit trail)

**步骤**:
1. `git ls-files | xargs grep -l '<legacy company string>'` 拿全文件 list(避免 untracked / dist 误删)
2. 对每个文件: 用 sed 删 file 起始的 `/^\/\*\*$/,/^ \*\/$/` 4 行块(精确匹配, 不误删其他 docstring)
3. 跑前 `git diff --stat` dry-run, 验证 N=156, 跑后再 `git diff` review
4. 跑后 `git status --short` 确认 156 文件 modified, 0 文件 untracked

**alternatives + 取舍**:

| Alternative | 描述 | 取舍 | 量化评估 |
|---|---|---|---|
| 手动逐文件删 | 用 IDE 批量 find&replace | ❌ | 不可重现, 无 audit trail, 156 文件易漏 |
| sed 单行命令(`sed -i '/<string>/d'`) | 只删一行 | ❌ | 漏了上下 3 行 wrapper, 留下空 docstring 块 |
| **sed 块匹配 + 脚本**(本 spec 选) | 4 行块精确匹配 + 脚本留 repo | ✅ | 可重现 + audit trail + 后续 maintenance |

### 3.3 Verify gate(T7 一部分)

- 重新跑 `git ls-files | xargs grep -l '<legacy company string>'` 应返回 0 命中
- mypy + ruff 全过(只删 comment 不影响代码)
- 前端 `npm run build` 不挂

### 3.4 风险 + mitigation

**Risk**: sed 块匹配可能误删非 copyright 块的 `/** ... */` docstring(如果某文件第 2 行恰好是别的 4 行 `/** */` 块)

**Mitigation**:
- 脚本只对每个文件的**起始 4 行**操作(用 sed `1,4` 范围 + `/^\/\*\*$/,/^ \*\/$/`)
- 跑前 dry-run, `git diff --stat` 验证每文件改动行数 = 4
- 跑后 `git diff` 逐文件 review(可用 `git difftool` 或 review tool)

| 文件 | 内容 |

### 7.2 Antd theme switching

- 用 Antd 5 的 `ConfigProvider` + `theme.token` 注入
- 路由级判断:
  - `/credit-report/* | /watchlist/* | /monitoring/* | /portfolio-monitoring/*` → banking theme
  - `/ticker/* | /screener/* | /chat/*` → retail theme
- 全局首次加载默认 retail theme(landing page 用 retail)

### 7.3 design-tokens.md 文档

**位置**: `docs/design-tokens.md`

**长度**: 1-2 页

**内容**:
- 设计基调: B/C 双风格 + 共用 tokens 的设计哲学(跟业务梳理 spec § 1.2 立论对齐)
- 配色规范:
  - banking 调色板(navy / dark slate / gold accent / red&green for 涨跌)
  - retail 调色板(white / soft blue accent / 浅灰 borders / red&green for 涨跌)
  - 共用语义色(success / warning / error / info)
- typography:
  - 中文字体栈(系统字体 fallback)
  - 数字字体栈(monospace for banking, proportional for retail)
  - 字号 scale (12 / 14 / 16 / 18 / 24 / 32)
- spacing scale(8px base)
- 关键组件示例(buttons / table / card / tag, B/C 各 1 套截图位)

### 7.4 alternatives + 取舍

| Alternative | 描述 | 取舍 | 量化评估 |
|---|---|---|---|
| 单一 theme | 统一风格 (A 或 B) | ❌ | 跟 § 1.2 立论(B 长报告 / C 短回答)分叉不一致 |
| 用户主题切换(light/dark toggle)| 让用户选风格 | ❌ | 增加 UX 复杂度, scope creep, 不是 v0.8.3-pre 重点 |
| 完整 component library + Storybook | 重做组件库 | ❌ | scope 失控, Antd 5 已经够用 |
| **路由级判断 + 共用 tokens**(本 spec 选) | 双 theme 文件 + ConfigProvider 注入 | ✅ | 工程量小(0.5-1 天), 跟立论对齐 |

### 7.5 风险 + mitigation

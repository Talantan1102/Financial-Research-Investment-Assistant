# 长期记忆评估体系重建 — 设计稿

> 日期:2026-06-04
> 状态:设计定稿待审
> 准绳:研发看板《跨会话记忆 · 怎么评估》(`dashboard/data/reports/cross-session-memory-eval.yaml`,#119)
> 决策方式:brainstorm 对话逐项拍板 + 一次 51-agent workflow 调研(知识更新故障模式,43 条核查存活)+ 工业界 session 结构调研

## 1. 背景与决策

现有 C.5 Plan 8 记忆 eval(50 golden + 4 metric + differential/poison)与看板研报的 6 维能力框架不一致:研报的 worked example 全是「第 2 次对话埋信息 → 隔干扰 → 第 N 次提问」的端到端形态,现有 golden 却用 `user_seed` 直接种图,绕过了抽取/冲突消解/跨 turn 分组整条写管线(开卷考);且 6 维里多跳/弃答/偏好三维实质空白。

**决策:绿地重建,不被旧资产绑架。** 旧 eval(`backend/eval/memory/`)保持原样不动、不再扩展;新体系另起目录,成熟后旧的整体退役。投毒 golden(写入安全)与 long_tail 监控(在线)不属于本次范围,保留。

### 已拍板的核心决策

| 决策 | 内容 |
|---|---|
| **对话流造题 + 双层断言** | 每个用例 = 多 session 对话脚本喂真实写管线;每个有效 session 喂完后**查真 PG 做确定性断言**(写管线层,零 LLM),最后提问评回答(读管线层,裁判+字符串)。失败时红灯直接指向写管线还是读管线 |
| **记忆不存持仓事实** | 持仓的唯一真相来源 = 持仓监控模块。chat 里的持仓陈述不入记忆图;问持仓路由到模块。记忆只管无结构化模块兜底的领地:观点/计划/风险画像/研究结论/人生事件 |
| **五个脚本族共 28 段 + 一本多题** | 脚本是写作单位,提问(probe)从同一段脚本派生(平均 2.5-3 个/段,共 ~85 题);每段脚本只过一遍写管线,所有提问共享这次写入 |
| **三档难度,比例约 30/40/30** | 直球档(基准线/金丝雀)/ 自然难档(间接指代、隔多个 session、要拼两条事实)/ 对抗档(假前提、推翻链、口误噪声)。输出**能力维度 × 难度档的分数表**,无门控逻辑(解读交给人) |
| **多轮对话、双边台词写死** | session 是「历史录像带」:用户台词逐字写死,助手台词写要点(终稿展开),只有最后的提问是活的。保可复现 + 可控信息位置;并白送「信息出现在助手嘴里、用户只确认」这类抽取刁钻题 |
| **session 长短两级分布** | 单个 session:短(2-3 轮,约一半,干扰为主)/ 中(5-8 轮,约 35%,有效信息主载体,对齐 LongMemEval)/ 长(12-20 轮,约 15%,信息埋深处,对齐 LoCoMo)。整段脚本:标准长度 8-12 个 session(约 22 段)/ 长程 25-35 个 session(约 6 段,每族至少 1 段,对齐 LongMemEval 的干扰深度) |
| **token 费用不设限,用例合写** | 评估跑分成本不是设计约束;每段脚本 Claude 出全稿、用户审「台词像不像真人、刁钻点够不够刁」 |

## 3. 知识更新维度的故障模式素材:八种机制 + 两个免费判法

(经 workflow 调研 18 条工业模式去重后定稿;其余维度的素材清单在逐族合写前用同样流程确定)

| 机制 | 内容 | 来源锚点 |
|---|---|---|
| **单事实更新** | 同一个冲突消解器的难度梯子,四种表达形态:直接推翻("看多观点我收回")/ 间接指代推翻("那只新能源清了")/ 部分更新(改持有期限但逻辑延续不丢)/ 撤回更正("我说错了") | LongMemEval 知识更新题人评仅 0.208;Mem0 #4896 矛盾被误判为新增 |
| **多跳叠加更新** | 沿链推理时每一跳都要取对版本 | MemoryAgentBench:所有方法 ≤6%(难度锚点:我们做到 30% 即可写进作品叙事) |
| **重复去重** | 重复陈述不重建边 + 反向:高度相似也不能误删(正反双断言) | Mem0 #4573(97.8% 垃圾记忆、同一句话存 200+ 次)、#1674(相似度 0.99999726 误删) |
| **作废历史可问** | 观点被推翻后问"我之前怎么看的",要能引用已作废版本——作废≠删除 | bi-temporal 架构招牌能力 |
| **涟漪传播** | 改一条原子事实后,派生结论要跟着变(清仓白酒→消费板块敞口/止盈提醒全要变) | RippleEdits(最佳方法仅 82.8%) |
| **读侧别名一致** | 更新后换别名问(600519/茅台/贵州茅台)不得答旧值;与「间接指代推翻」同根(都是实体对齐),但那个死在写侧、这个死在读侧——数据库断言恰好能区分两种死法 | 知识编辑 generality 轴 |
| **时间戳语义** | 有效起始时间取事件发生时间而非录入时间 + 相对表述("上周")锚定为绝对日期 + 乱序回填按事件时间裁决——一个机制的因、相、果,一段脚本全压到 | Graphiti #1489 / 官方自认乱序弱点 |
| **噪声对抗** | 新信息其实是口误,系统不该盲从"新的总是对"(撤回更正的镜像:那个考"旧的错了要认",这个考"新的错了别盲从") | Zep 自述"一律优先新信息"且无兜底 |

**两个免费判法**(体系架构的红利,不占脚本):

- **交换顺序双跑**:冲突用例把检索结果交换顺序跑两遍、断言答案一致且取新——不需要专门的故事,做成 runner 开关挂在冲突题上白拿(防"答案随检索排序漂移")。
- **确认语与库对账**:数据库断言天然抓"嘴上说记了、库里没有"的假确认,不需要独立题;故意注入写失败看是否谎报,归 chaos 测试线,不进 golden。

## 3b. 偏好一致维度素材:四场景 + 四判法

(2026-06-04 第二轮 workflow 调研,99 agent / 84 条核查存活,拍板定稿)

场景型:**过度泛化**(一次性"想搏一把短线"被套到养老定投咨询;含"一次性情景固化"变体)、**谄媚翻转**(用户施压"我就想 all in",74% 违规案例第 2 轮就发生;记录首次让步轮次)、**长对话偏好遗忘**(5 轮 80%→30%、10 轮破 10%,PrefEval)、**隐式偏好识别**(连续几个 session 对某板块说"又跌了""没信心",从不明说,要推断出回避)。

判法型:**知行不一双轨断言**(同一题配"复述偏好"+"扫描推荐里有无禁标的"两个断言,背离即违规;跨模型知行不一率 8-99%,且 LLM 裁判只能抓到 15% 的违背——偏好题必须程序化扫标的清单,不能只靠裁判)、**沉默式作废**(旧偏好静默压过当前明示,且不报冲突)、**偏好幻觉溯源**(模型声称的每条历史偏好须能溯源到真实 turn,复用项目已有 evidence_quote 校验)、**作用域标签断言**(会话级偏好不得晋升全局)。

## 3c. 时间推理维度素材(读侧):三场景 + 五判法 + 一回归断言

写侧时间戳语义已归知识更新维度;"旧事实过期未失效"经查重划归知识更新(同一故障不跨维度重复计分)。

场景型:**时间窗过滤**("上个月那只新能源的目标价"——LongMemEval 实测加时间窗过滤召回 +6.8~11.3%)、**跨 session 时序链**("把我对这只票的看法演变按时序讲一遍"——记忆系统 26-37% vs 长上下文 59-82%)、**真实流逝时间盲视**(行情是 5 分钟前还是上周的,该不该重新取数;后置为机动脚本候选)。

判法型:**多事实整合难度轴**(同组事实出单事实/多事实两版,单 89-93% vs 多事实排序 24-36%)、**相对时间区间换算断言**(中间产物"解析出的日期区间"单独断言)、**时长算术断言**(容差 0 天,单独统计恰差一天的比例)、**位置置换鲁棒性**(证据挪到上下文头/中/尾答案应稳定)、**recency 压制检验**(久未提及但仍有效的长期纪律不被近期噪声挤出 top-5)。

回归断言:**时间轴坍缩自检**(排序题前先断言库里事件时间戳有真实分布、非全等)。

## 3d. 克制弃答维度素材:七场景 + 三判法

场景型:**假前提编答**(问从未发生的"那笔港股腾讯该止盈吗")、**幻觉填空**(编一个从没说过的成本价)、**信息不足碎片**("聊过想配新能源但没定标的"→问"我们定的那只新能源龙头"——半吊子上下文比没上下文更危险:无上下文幻觉 10.2% vs 不足上下文 66.1%)、**近似记忆冒充**("A 股银行股息率高适合我"→"港股银行也该买吧?"语义像但从未涉及,不该外推)、**检索相关但无答案仍强答**(RGB negative rejection:拒答率仅 24.67%/5.33%)、**谄媚倒戈**(模型正确说"没聊过比特币",用户坚称"我明明上周问过",不应倒戈)、**过度拒答陷阱**(显式补一组"可答 A 股题混入无关检索记忆",防"全程保守拒答"刷分)。

判法型:**可答题拒答一律 0 分**(反蹭分守卫)、**弃答必须实质纠错**(光说"不确定"不给分,要指出前提错在哪并给正确结论)、**只认最终答案**(推理链里的犹豫不算弃答)。

明确不收:假阳性记忆复用(偏 agent 经验复用,离底料远)、知识边界冷门事实(模型能力题,超记忆评估射程)、求认同误判(对话品质题,先记不收)。

## 3e. 不变量开关家族(跨维度统一判法)

四个维度各自冒出同一家族的判法——「同一道题变换一个无关因素,断言答案不变」:交换检索顺序(知识更新)、证据位置置换(时间)、相对/绝对日期配对(时间)、复述/行为双轨(偏好)。runner 实现为统一的不变量开关机制,逐题按需挂。

**明确不收**(调研里出现但不适用):梯度相似度问题(改模型权重的知识编辑特有,外置数据库记忆不存在该机制)、库膨胀/检索污染(长跑容量问题,归 long_tail 监控线)、压缩丢细节(我们 episode 全文保留,前提不成立)。**改挂别的维度**:过度泛化(一次性偏好被到处注入)→ 偏好一致维度;沉默式作废(计划过期但用户没显式说)→ 偏好维度的时效题。

## 4. 数据 schema(脚本 yaml)

```yaml
script_id: viewpoint-baijiu          # 机器标识用英文 slug,人读靠 title
title: "白酒观点演化"
family: 观点演化族
substrate: 观点演化(无结构化模块兜底,纯记忆领地)
sessions:
  - n: 1
    date: 2025-01-06
    length: 中                       # 短/中/长
    turns:
      - u: "白酒这波回调你怎么看,我最近在集中研究这个板块"
      - a: "(分析回调原因,提到批价、库存周期)"     # 助手台词写要点
      - u: "我研究下来的结论是高端白酒值得拿三年,核心逻辑是提价权还在"
      - a: "(回应,追问:三年基于什么周期?)"
      - u: "渠道库存出清加上下一轮提价窗口,差不多就是这个时间"
  - n: 2
    date: 2025-01-15
    length: 短
    turns:
      - u: "美联储这次议息怎么看"
      - a: "(简要分析)"
db_assertions:                       # 写管线层:每个有效 session 喂完后查真 PG
  - after: 1
    assert:
      - {type: fact_active, subject: 白酒观点, value_contains: ["看多", "提价权"]}
probes:                              # 读管线层:全部 session 喂完后活跑
  - tier: 直球
    dimension: 知识更新
    q: "我现在对白酒什么看法?"
    expect_contain: ["中性"]         # 字符串硬校验
    expect_not: ["看多", "三年"]
    judge_rubric: "..."              # LLM 裁判按 rubric 判,与字符串校验双保险
    swap_order_invariant: true       # 可选:交换检索顺序双跑
```

实施的第一个任务即合写「白酒观点演化」完整稿(9 个 session,压单事实更新的前半梯子「直接推翻+部分更新」,重复去重、时间戳语义搭车),定稿后作为其余 27 段的格式范本。

## 5. Runner 架构

```
对脚本里的每个 session:                  # 写阶段
    喂进真实写管线(抽取→冲突消解→入图入向量)
    若该 session 配了数据库断言:
        查真 PG 跑断言                   # 确定性,零 LLM
对脚本里的每个提问:                      # 读阶段
    answer = 真实读管线(检索+生成)
    字符串硬校验(expect_contain / expect_not)
    LLM 裁判按 rubric 判
    若开了交换顺序双跑:
        answer2 = 读管线(检索结果交换顺序)
        断言两次答案一致
```

输出:**能力维度 × 难度档分数表**(知识更新/单跳召回/多跳推理/时间推理/克制弃答/偏好一致/持仓仲裁 × 直球/自然难/对抗),外加写管线层数据库断言通过率单列。无门控、无聚合总分。

判分纪律(继承旧体系的好底色):能确定性的全确定性(数据库断言/字符串校验/路由工具断言),裁判只管开放题且必配 rubric + 字符串双保险。

## 6. 范围与待办

**本 spec 范围内**:schema 定稿、runner、五族 28 段全部(四个维度素材清单已全齐,见 3-3e 节)。
**素材沉淀**:四维度故障模式 + 造题建议已发布为看板研报《长期记忆 · 故障模式与造题》(`/eval/report/memory-failure-modes`),与《跨会话记忆 · 怎么评估》互为姊妹篇。
**范围外**:投毒/chaos/long_tail(保留现状)、A/B 在线评估、旧 eval 退役时点(新体系跑通后另议)。

## 7. 验收

- 28 段脚本全部双人定稿(Claude 草稿 + 用户审真实感)
- runner 全量跑通,输出能力维度 × 难度档分数表
- 直球档通过率作为体系自检:若直球档大面积红,先怀疑评估 harness 自身而非记忆系统
- 每段脚本至少 1 个提问在首次真跑时抓到过真实故障,或证明该机制系统已扛住(两者都是信息)

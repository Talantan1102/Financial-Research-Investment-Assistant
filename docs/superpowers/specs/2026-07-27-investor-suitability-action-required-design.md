# 投资者适当性与 action_required 对话结果设计

**日期：** 2026-07-27
**状态：** 已确认
**范围：** 模拟交易的市场权限前置校验、独立权限申请流程，以及 Agent 无法完成用户意图时的通用 `action_required` 结果

## 1. 背景与问题

当前模拟交易已经支持自选股写入、模拟订单审批、撮合、部分成交、撤单和结算，也能按板块应用涨跌幅、整手、T+1 等交易规则。但下单前尚未体现完整的投资者适当性与市场准入：系统可以判断订单价格和数量是否合法，却没有统一判断当前用户是否具备主板、创业板、科创板或北交所的买入权限。

权限申请本身是 Agent 时代以前就存在的确定性业务流程。它包含资料确认、条件校验、风险揭示书签署、权限开通和审计，不应由大模型替用户办理。Agent 的职责是识别前置条件、解释阻塞原因并提供申请入口。

本设计解决两个问题：

1. 下单前如何确定性地检查用户是否有对应市场权限。
2. Agent 已正常完成本轮，但用户意图因外部前置操作尚未完成时，如何表达并安全续接。

## 2. 核心决策

### 2.1 权限申请独立于 Agent

Agent 只保留以下只读能力：

- 查询当前市场权限；
- 检查一笔订单是否具备继续条件；
- 获取权限申请页面链接。

下列写操作不暴露为 Agent 工具：

- 修改投资者适当性资料；
- 签署风险揭示书；
- 开通、限制或撤销市场权限。

这些操作全部由独立权限申请页面和确定性后端服务完成。

### 2.2 已开通用户不进入申请流程

权限检查是申请流程的入口门：

```text
用户请求交易
  ↓
查询当前权限
  ├─ 已开通：继续订单校验
  └─ 未开通：返回申请入口，本轮结束
```

已开通用户不会触发重复评估、重复签署或重复写入。

### 2.3 用户可在申请流程任一步终止

权限申请页面允许用户拒绝提供资料、取消修改、拒绝签署、关闭页面或因超时退出。开通权限是流程末尾的原子动作；在此之前退出，不获得任何部分权限。

已被用户单独确认的资料修改可以保留；已经完成的适当性评估作为不可覆盖的审计记录保留；未明确确认的风险揭示书不得记录为已签署。

### 2.4 签署与开通在一个事务中完成

用户最终确认时，后端在同一个数据库事务中：

1. 重新读取当前资料和规则版本；
2. 重新校验适当性条件；
3. 记录风险揭示书签署；
4. 开通对应市场权限；
5. 一起提交。

任一步失败则整体回滚，避免出现“已经签署但未开通”或“已经开通但没有有效签署记录”。

### 2.5 外部操作后开启新 Run

权限不足时，旧 Run 正常结束，不长期暂停等待用户。申请成功后也不自动恢复旧 Run、不自动执行原订单。用户返回对话并主动点击“继续”或重新发送消息，产生新 Run。

新 Run 必须重新检查：

- 市场权限；
- 最新行情；
- 交易时段；
- 账户余额；
- 可卖持仓；
- 证券停牌或禁买状态；
- 价格、数量和订单规则。

旧 Run 的行情快照、资格判断和订单确认均不可复用为执行授权。

## 3. 现实规则基线

第一版支持主板、创业板、科创板和北交所。规则数值进入版本化配置，不硬编码在订单服务中。

| 市场 | 最近 20 个交易日日均资产 | 证券交易经验 | 风险揭示要求 |
|---|---:|---:|---|
| 主板 | 无专项金额门槛 | 无专项年限门槛 | 新开 A 股账户的普通投资者首次参与前签署主板风险揭示书 |
| 创业板 | 不低于 10 万元 | 不少于 24 个月 | 首次申请开通时签署创业板风险揭示书 |
| 科创板 | 不低于 50 万元 | 不少于 24 个月 | 首次申请开通时签署科创板风险揭示书 |
| 北交所 | 不低于 50 万元 | 不少于 24 个月 | 按北交所适当性要求签署风险揭示书 |

本系统是模拟交易产品，不连接真实券商验资。用户提交的最近 20 个交易日日均资产属于模拟环境中的主动声明，页面必须明确说明它不是券商认证结果。

权限分别表达申购、买入和卖出能力。适当性条件不满足或买入权限受限时，不应因此阻止用户卖出已有持仓。

## 4. 用户流程

### 4.1 首次进入模拟交易

```text
创建模拟账户
  ↓
主板：阅读并签署风险揭示书
  ↓
创业板 / 科创板 / 北交所：
填写并确认模拟资产与交易经验
  ↓
确定性规则评估
  ├─ 不满足：展示具体差距，结束申请
  └─ 满足：展示对应风险揭示书
                ↓
             用户最终确认
                ↓
             原子记录签署并开通权限
```

### 4.2 Agent 发现权限不足

```text
用户：买入中芯国际 100 股
  ↓
Agent 识别为科创板股票
  ↓
确定性服务返回“科创板权限未开通”
  ↓
Agent 解释原因并展示“申请科创板权限”链接
  ↓
本轮以 completed + action_required 结束
```

### 4.3 用户完成申请后返回

```text
用户完成或取消独立申请流程
  ↓
用户主动返回对话并点击“继续”
  ↓
创建新 Run
  ↓
重新读取权限和全部订单条件
  ↓
重新生成订单预览
  ↓
用户重新确认
  ↓
创建模拟订单
```

申请成功不等于同意下单。权限确认和订单确认是两个独立的用户决策。

## 5. 数据模型

### 5.1 InvestorSuitabilityProfile：投资者适当性资料

表示用户在模拟环境中主动确认的投资条件。

| 字段 | 中文解释 |
|---|---|
| `user_id` | 用户编号，用于区分不同用户 |
| `investor_type` | 投资者类型，例如普通个人、专业个人或机构 |
| `risk_level` | 用户风险承受能力等级，例如 C1 至 C5 |
| `securities_experience_months` | 从首次证券交易开始计算的交易经验月数 |
| `declared_average_assets_20d` | 用户声明的最近 20 个交易日证券账户日均资产；不是当前单日余额，也不是系统真实验资 |
| `assessed_at` | 最近一次完成风险评估的时间 |

### 5.2 MarketEntitlement：市场交易权限

表示模拟账户当前在某个市场能够进行哪些操作。

| 字段 | 中文解释 |
|---|---|
| `account_id` | 模拟交易账户编号 |
| `market` | 权限对应的市场或板块，例如主板、创业板、科创板、北交所 |
| `status` | 当前权限状态 |
| `can_buy` | 是否允许买入该市场证券 |
| `can_sell` | 是否允许卖出该市场已有持仓 |
| `can_subscribe` | 是否允许参与该市场新股申购 |
| `rule_version` | 当前权限依据的市场准入规则版本 |
| `enabled_at` | 权限成功开通时间 |
| `restricted_at` | 权限被限制的时间；未限制时为空 |
| `reason_code` | 开通、拒绝、限制或撤销的确定性原因代码 |

权限状态：

| 状态 | 中文解释 |
|---|---|
| `not_applied` | 用户尚未申请 |
| `pending_disclosure` | 条件满足，等待签署风险揭示书 |
| `enabled` | 权限已开通 |
| `restricted` | 权限受限，例如只允许卖出 |
| `revoked` | 权限已经撤销 |

### 5.3 SuitabilityAssessment：适当性评估记录

表示一次权限申请使用了什么资料、规则和判断结果。记录不可覆盖。

| 字段 | 中文解释 |
|---|---|
| `account_id` | 发起申请的模拟账户编号 |
| `market` | 本次申请的市场或板块 |
| `submitted_snapshot` | 申请时的资产、经验、风险等级等完整资料快照 |
| `decision` | 本次评估结果，例如通过或拒绝 |
| `failed_conditions` | 未通过的具体条件及差距；通过时为空 |
| `rule_version` | 本次评估使用的准入规则版本 |
| `created_at` | 本次评估发生时间 |

### 5.4 RiskDisclosureAcceptance：风险揭示书签署记录

表示用户签署过哪一市场、哪一版本的风险揭示书。

| 字段 | 中文解释 |
|---|---|
| `account_id` | 签署风险揭示书的模拟账户编号 |
| `market` | 风险揭示书对应的市场或板块 |
| `disclosure_version` | 用户签署的风险揭示书版本 |
| `accepted_at` | 用户明确确认签署的时间 |
| `source` | 签署来源；第一版只允许独立权限申请页面 |

### 5.5 MarketAccessRule：市场准入规则

表示某一市场在一个生效期间内要求满足什么条件。

| 字段 | 中文解释 |
|---|---|
| `market` | 规则适用的市场或板块 |
| `effective_from` | 规则开始生效的日期 |
| `minimum_average_assets_20d` | 最近 20 个交易日日均资产最低要求；没有专项门槛时为空 |
| `minimum_experience_months` | 最低证券交易经验月数；没有专项门槛时为空 |
| `required_disclosure_version` | 当前必须签署的风险揭示书版本 |
| `rule_version` | 整套准入规则的唯一版本号 |

### 5.6 EntitlementApplication：权限申请

表示一次独立权限办理流程，支持取消和超时。

| 字段 | 中文解释 |
|---|---|
| `application_id` | 本次权限申请编号 |
| `account_id` | 申请所属的模拟账户编号 |
| `market` | 申请开通的市场或板块 |
| `status` | 当前申请状态 |
| `assessment_id` | 本次申请关联的适当性评估记录编号 |
| `started_at` | 申请开始时间 |
| `completed_at` | 申请完成、取消、拒绝或过期的时间 |
| `cancel_reason` | 用户取消或系统终止的原因；未取消时为空 |

申请状态：

| 状态 | 中文解释 |
|---|---|
| `in_progress` | 用户正在办理 |
| `awaiting_information` | 等待用户补充或确认资料 |
| `awaiting_confirmation` | 条件满足，等待最终签署确认 |
| `cancelled_by_user` | 用户主动终止申请 |
| `expired` | 用户长时间未操作，申请失效 |
| `rejected` | 适当性条件不满足 |
| `completed` | 权限成功开通 |

## 6. 证券识别与订单资格判断

### 6.1 InstrumentTradingProfile：证券交易属性

表示一只证券属于什么市场以及当前适用哪些交易规则。

| 字段 | 中文解释 |
|---|---|
| `ts_code` | 带交易所后缀的证券唯一代码，例如 `688981.SH` |
| `name` | 证券名称，例如中芯国际 |
| `exchange` | 所属交易所，例如上交所或深交所 |
| `board` | 所属板块，例如主板、创业板或科创板 |
| `instrument_type` | 证券类型；第一版只处理股票 |
| `risk_warning` | 是否为 ST、*ST 等风险警示证券 |
| `buy_enabled` | 当前是否允许买入 |
| `sell_enabled` | 当前是否允许卖出 |
| `suspended` | 当前是否停牌 |
| `lot_size` | 一手包含的股数 |
| `t_plus_one` | 今天买入后是否需要等到下一交易日才能卖出 |
| `rule_version` | 当前证券交易规则版本 |

### 6.2 OrderEligibilityDecision：订单资格检查结果

表示一笔拟议订单是否允许进入订单确认步骤。该结果由确定性规则产生，不由大模型判断。

| 字段 | 中文解释 |
|---|---|
| `allowed` | 是否允许进入订单确认步骤 |
| `market` | 证券所属的市场或板块 |
| `required_permission` | 该操作需要的市场权限 |
| `permission_status` | 用户当前权限状态 |
| `blocking_reasons` | 阻止继续下单的确定性原因列表 |
| `warnings` | 不阻止下单，但必须向用户提示的风险列表 |
| `rule_versions` | 本次判断使用的适当性规则和交易规则版本 |
| `checked_at` | 完成检查的时间 |

检查顺序：

1. 识别证券、交易所和板块；
2. 检查证券是否停牌、禁买或禁卖；
3. 检查用户是否拥有对应市场权限；
4. 分别检查申购、买入或卖出能力；
5. 检查风险揭示书版本是否有效；
6. 检查账户状态、余额和可卖持仓；
7. 检查交易时间、订单类型、价格和数量；
8. 允许后才生成订单预览。

权限服务不可用、证券无法分类或规则版本缺失时必须拒绝继续，不得默认放行。

## 7. action_required 对话结果

### 7.1 语义

`action_required` 不是新的顶层 Run 生命周期状态。它表示：

```text
Run 状态：completed
业务结果：action_required
```

即 Agent 已正常完成本轮，但用户的最终业务意图尚未完成，需要用户在对话外完成一项操作后主动回来。

### 7.2 结构化字段

| 字段 | 中文解释 |
|---|---|
| `run_status` | Agent 本轮是否正常结束；本场景为 `completed` |
| `outcome` | 用户业务目标的完成情况；本场景为 `action_required` |
| `action_type` | 用户下一步需要完成的操作类型，例如申请市场权限 |
| `action_url` | 外部确定性业务流程入口，只用于页面导航，不携带可执行授权 |
| `action_label` | 按钮上展示的中文文字 |
| `resume_hint` | 用户完成外部操作后如何继续的提示 |
| `intent_summary` | 尚未完成的原始意图摘要，仅用于帮助用户和新 Run 理解上下文 |

示例：

```json
{
  "run_status": "completed",
  "outcome": "action_required",
  "action_type": "apply_market_permission",
  "action_url": "/permissions/star-market/apply",
  "action_label": "申请科创板权限",
  "resume_hint": "申请完成后回来继续下单",
  "intent_summary": "买入中芯国际 100 股"
}
```

### 7.3 安全边界

`action_url` 只包含页面定位，不直接携带“为某用户开通权限”的指令。申请页面根据当前登录身份、账户和数据库状态重新建立申请上下文。

`intent_summary` 可以保存证券、方向、数量和订单类型，但不得保存或复用：

- 已批准订单；
- 旧行情价格；
- 旧余额校验结果；
- 旧权限判断；
- 旧订单确认；
- 可直接执行的授权凭证。

### 7.4 通用性

第一版由市场权限场景落地，但 `action_required` 是通用结果，后续可以复用于实名认证、风险测评、模拟资金补充、文件上传、知识库文档导入和外部数据源配置。

## 8. 接口与组件边界

### 8.1 Agent 侧只读能力

| 能力 | 中文作用 |
|---|---|
| `get_market_entitlements` | 查询当前模拟账户在各市场的权限状态 |
| `check_order_eligibility` | 确定性检查拟议订单能否进入确认阶段 |
| `get_entitlement_application_link` | 生成或返回对应市场权限申请页面入口 |

### 8.2 权限申请服务

独立服务负责：

- 创建和恢复权限申请；
- 收集经用户确认的模拟资料；
- 调用版本化规则完成适当性评估；
- 展示当前版本风险揭示书；
- 原子记录签署并开通权限；
- 处理取消、拒绝、超时、限制和撤销；
- 写入完整审计记录。

### 8.3 订单服务

订单服务只消费当前有效的 `MarketEntitlement` 和 `OrderEligibilityDecision`，不自行办理权限申请，也不接受 Agent 传入的“用户声称已有权限”作为放行依据。

## 9. 异常与边界处理

| 情况 | 处理方式 |
|---|---|
| 权限查询失败 | 停止下单并提示稍后重试，不猜测权限 |
| 申请链接生成失败 | 提示用户从账户权限页面进入，本轮仍正常结束 |
| 打开申请页时权限已开通 | 页面直接显示已开通，不重复办理 |
| 用户中途退出 | 申请结束或保持可恢复状态，权限不变 |
| 申请成功后用户未返回 | 不恢复 Agent，不自动执行订单 |
| 用户回来时仍未开通 | 再次说明当前状态并提供申请入口 |
| 用户回来时行情、余额或时间变化 | 使用最新数据重新检查和生成预览 |
| 证券停牌或不可买 | 即使权限已开通，也拒绝创建订单 |
| 同一申请被重复提交 | 通过幂等键返回同一业务结果，不重复开通 |
| 签署完成但事务提交失败 | 签署和权限开通一起回滚 |
| 规则版本在办理期间变化 | 最终确认前重新评估，提示用户按新规则继续或重新申请 |

## 10. 验收与测试

### 10.1 核心场景

1. 用户已有权限时直接进入订单校验，不出现申请入口。
2. 用户缺少权限时，本轮以 `completed + action_required` 结束。
3. 用户不点击链接时，不创建权限或订单。
4. 用户进入申请页后取消，权限保持不变。
5. 用户拒绝提供资料或拒绝签署时，申请终止且不开通权限。
6. 用户完成申请但不返回时，不自动执行订单。
7. 用户完成申请并主动返回时，创建新 Run。
8. 新 Run 重新检查权限、行情、余额、持仓、时间和证券状态。
9. 新 Run 重新要求用户确认订单。
10. 旧 Run 的确认信息不能用于新 Run。
11. 部分权限受限时，买入和卖出能力分别生效。
12. 权限服务不可用时，系统拒绝继续，不默认放行。

### 10.2 数据一致性

- 签署记录与权限开通必须同事务提交；
- 每次评估保留独立快照和规则版本；
- 权限重复申请和重复确认必须幂等；
- 规则升级不能改写历史评估；
- 取消申请不能产生有效签署或权限；
- 所有权限变化保留用户、账户、来源、时间和原因。

### 10.3 Agent 评估

新增 golden cases 验证：

- Agent 正确识别不同股票所属板块；
- 权限不足时不调用模拟下单写工具；
- 返回正确的申请市场和申请链接；
- 不声称已经为用户开通权限；
- 用户返回后重新检查，不复用旧授权；
- 权限查询异常时采取拒绝继续的安全默认值。

## 11. 第一版范围

### 包含

- 主板、创业板、科创板和北交所权限；
- 独立权限申请页面和确定性后端服务；
- 版本化准入规则和风险揭示书；
- Agent 只读权限查询与订单资格检查；
- 通用 `action_required` 结果和前端操作卡片；
- 用户返回后开启新 Run；
- 权限、申请、评估、签署、订单和 Run 的审计关联。

### 不包含

- 真实券商账户连接或真实验资；
- Agent 代替用户填写、签署或开通权限；
- 权限申请完成后自动恢复旧 Run；
- 自动执行原订单；
- 融资融券、股票期权、港股通、可转债等复杂产品权限；
- 用大模型替代确定性适当性规则。

## 12. 完成定义

只有在以下条件同时满足时，第一版才算完成：

1. 权限不足的订单不会进入模拟下单写路径；
2. 用户能够从 `action_required` 卡片进入独立权限申请流程；
3. 用户可在申请任一步终止，且不会获得部分权限；
4. 风险揭示书签署与权限开通原子提交；
5. 申请完成后只能由用户主动开启新 Run；
6. 新 Run 重新校验全部易变条件并重新请求订单确认；
7. 单元、集成、前端和 Agent golden cases 均提供实际通过证据。

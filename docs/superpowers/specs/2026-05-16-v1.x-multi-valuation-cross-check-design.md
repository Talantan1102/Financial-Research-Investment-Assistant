# v1.x A5a — 多模型估值 cross-check 设计

## § 1. 问题陈述

### 1.1 现状

v1.x A4 已 ship 后,Writer 产出的 `InvestmentDueDiligenceReport.ValuationAnalysis` schema **只有单一估值视角**(`pe_ratio` / `pe_historical_percentile` 等),实际只是 PE band 单 lens。Writer prompt 让 LLM 自己叙述"估值合理性",**没有多模型 cross-check**,产生两个 v0.8.5 reframe 时已识别但未根治的问题:

1. **数字 hallucination 风险**:LLM 自己拍"合理估值"数字,容易脱离任何严肃估值方法。v0.8.5 已经把 `recommendation` / `position_size_pct` 推给 Python `compute_*` helper(deterministic 数字 + LLM 叙事范式),但**估值"理论价"还是 LLM 单独叙事**,没承接 v0.8.5 主线。
2. **单 lens 信号弱**:严肃尽调标配 2-4 个独立估值方法 cross-check(PE / EV/EBITDA / PB / DCF),用一致性验证假设正确;**单 lens 等于没 cross-check**,出错没人挑战。

### 1.2 业务驱动 — 为什么是这个 PR

A5a 是 v1.x **"双 hallucination 防御"** 计划的第一块:
- **A5a(本 PR)** 防 **数字 hallucination** — 多模型估值 cross-check + Python deterministic helper
- **A5b(下个 PR,brainstorm 待开)** 防 **叙事 hallucination** — bull/bear multi-agent debate

把数字层夯实在前(A5a),让 A5b debate agent 有真实多模型数字作 ammunition,**两个 PR 自然连通**:数字层 → 叙事层。

### 1.3 portfolio 价值

本 PR 提供 3 个简历讲故事点:
1. **沿用并强化 "数字 Python / judgment LLM" 主线**(v0.8.5 reframe 起,v1.x A4 中场承接,v1.x A5a 在估值层落地)
2. **行业标准 mapping 的工程化**:industry router(deterministic 骨架 + LLM judgment override),复刻研究员 30% 规则 + 70% 判断 的工作流
3. **outlier diagnosis 的 algorithmic explainability**:cross-check severe divergence 时,LLM 显式诊断哪个 lens 偏离 + 假设错在哪 — 是真实研究员工作流的 LLM-mapping

## § 2. 业界 mindset(基于真实卖方 / 投行 / 买方实践)

### 2.1 估值的根本

公司值多少钱 = 它能给你产生多少未来现金。所有估值方法都是这个根本问题的**间接代理(proxy)**:
- **PE** 用今年利润作 proxy
- **EV/EBITDA** 用今年 EBITDA(剥离财务/折旧)作 proxy
- **PB** 用净资产作 proxy
- **DCF** 直接预测未来现金流

不同公司类型用不同 proxy,是因为某些 proxy 对某类公司**信号密度高**,对另一类公司**信号密度低或失真**。

### 2.2 真实研究员的工作流

**Step 1 — 选模型**(行业 mapping):
| 公司类型 | 主估值 | 辅助 | 不用 |
|---|---|---|---|
| 消费 / 品牌(茅台) | PE + DCF | 行业可比 | PB(轻资产)|
| 银行(招行) | PB + ROE | P/PPOP | DCF(现金流难定义)|
| 周期股(钢铁) | EV/EBITDA + 历史 PE band | PB | 当前 PE(波动)|
| 重资本 / 通信(中国移动) | EV/EBITDA + DCF | PB | PE(折旧扭曲)|
| 公用事业 | PB + 股息折现 | EV/EBITDA | 当前 PE |
| 早期 / 亏损公司(新能源车) | DCF + 比较交易 | P/S | PE(无盈利)|

**Step 2 — 跑数字**:
- 行业默认 mapping 选 2-3 lens(很少 4 个全跑,因为冗余)
- **边界 case** (腾讯既是消费又是科技平台 / 美团既是消费又是平台型科技)由研究员**基于 judgment 调整** mapping

**Step 3 — DCF 假设(最难)**:
- **增长率优先级**:管理层指引 > 卖方共识 > 历史外推。每个数字必须有 supporting evidence
- **永续增长率**:行业标准 2-3%(对齐 GDP 长期增长,不能超过经济体长期 GDP 增速;数学硬约束:必须 < WACC)
- **WACC**:**部门级 team view 统一管控**,不是每个分析师自己拍;典型范围 7-12%,sector-specific
- **必须做 base/bull/bear 三场景**,按概率加权得 expected value
- **必须做 sensitivity 表**(WACC ±1-2% × Terminal Growth ±1-2%);terminal value 占总价值 60-80%,假设小动结果飘很大

**Step 4 — cross-check**:
- consistent → narrative 说"4 lens 一致"
- moderate divergence → narrative 解释偏离原因
- **severe divergence → 不是 bug,是 signal**;研究员**回去诊断哪个 lens 的假设错**,不是取平均

## § 4. 决策 Q2 — 模型选择:全 4 + 行业 router

### 4.1 问题

PE / EV/EBITDA / PB / DCF 4 个模型,做几个?

### 4.2 Alternatives

| 选项 | 描述 | 适用场景 | 缺点 |
|---|---|---|---|
| **a. 全 4 模型 全跑** | 每个公司都跑 4 模型 | 简单 | 边界冗余(茅台 PE/EV/EBITDA 高度相关 → echo 不是 cross-check)|
| **b. 只做 PE + DCF**(2 模型最小)| 消费股 case | 简洁 | 银行 / 重资本 case 没法做 |
| **c. 全 4 + 行业 router 选激活** | router 按公司类型激活 2-3 模型 | **完整复刻行业实践** | router 工程量大 |

1. **完整对应行业 mapping 表**(§ 2.2 Step 1)
2. **未来 use case reusable**:平台未来要处理银行 / 地产 / 重工业,4 模型 + router 已有
3. 简历讲故事最深(industry router 是有意义的工程决策点)

### 4.4 评估

- LoC ≈ 4 helper 各 ~100 行 + router ~150 行 + orchestrator ~100 行 = ~650 行
- 关键 trade-off:行业 mapping 表的覆盖度。spec § 5 详述 router 的决定性 mapping + LLM override 二层结构

## § 5. 决策 Q3 — Router 实现:混合(deterministic + LLM judgment override)

### 5.1 问题

行业 → active_models 的 mapping 怎么实现?

### 5.2 Alternatives

| 选项 | 描述 | 优 | 缺 |
|---|---|---|---|
| **A. 纯 deterministic rule-based** | `industry_code → mapping table → active_models` | 可解释 / 0 LLM cost / 可测试 | 边界 case 漏(腾讯/美团)、新概念股(AI / 元宇宙)mapping 缺位 |
| **B. 纯 LLM-based** | `ValuationModelSelector` agent,输入公司信息,LLM 输出 active_models + 理由 | 灵活 / 边界 case OK | 每次 LLM call / 不一致风险 / 不可测试 |
| **C. 混合(deterministic 骨架 + LLM judgment override)** | 第一层 deterministic mapping;第二层 LLM analyst 看公司 narrative 可 override + 给 reasoning | **完整复刻研究员**(30% 规则 + 70% 判断) / 80% case 不调 LLM / 边界 case 可 override | 工程量略大(2 层都要 build)|

### 5.3 选择 C

跟 § 6 (DCF 假设)、§ 7(outlier diagnosis)的范式一致:**Python deterministic 骨架 + LLM judgment 局部 override**。

## § 6. 决策 Q4 — DCF 假设来源:Python deterministic + LLM override 增长率(局部)

### 6.1 问题

DCF 三个关键假设(增长率 / 永续增长率 / WACC),谁来给,怎么给?

### 6.2 业界做法回顾(§ 2.2 Step 3)

- 增长率优先级:管理层 > 卖方共识 > 历史外推
- 永续增长率:行业 2-3% 标准
- WACC:**部门级 team view**,不是分析师拍
- **必须做 base/bull/bear + sensitivity**

### 6.3 我们的方案

| 假设 | 处理 | 来源 |
|---|---|---|
| **未来 10 年增长率** | Python `compute_growth_trajectory()` **3 场景输出**(base/bull/bear) | 优先级:tushare `get_forecast` 业绩预告 → 历史 5 年 revenue/profit decay 外推 + 衰减到永续 |
| **LLM analyst override base 场景** | 可调整 base 增长率(给 ≤200 char reasoning),不动 bull/bear | 模拟"研究员调增长率"高频动作 |
| **永续增长率** | 行业 default 表(消费 2.5% / 周期 2% / 科技 3% / 金融 2% / 公用 2%),100% deterministic | GDP 锚,不让 LLM 改 |
| **WACC** | 行业 default 表 + 公司 β 调整 + 杠杆调整,100% deterministic | "team view" 风格;基于 CAPM 简化版 |
| **Sensitivity 表** | Python `compute_dcf_sensitivity()` 输出 5×5 矩阵 | WACC ±1%/±2% × Terminal ±0.5%/±1% |
| **三场景输出** | DCF 输出 `dcf_base / dcf_bull / dcf_bear` 三值 | 默认概率 50%/25%/25% |

### 6.5 增长率 decay 模型

```python
def compute_growth_trajectory(
    historical_growth: list[float],  # 5 年实际增速
    forecast_growth: float | None,   # tushare get_forecast,如有
    industry_terminal: float,        # 行业永续
    scenario: Literal["base", "bull", "bear"],
) -> list[float]:
    """生成 10 年增速序列,从启动值衰减到永续。

    - base: 启动值 = avg(historical) 或 forecast(if available);线性 decay
    - bull: 启动值 = max(historical, forecast) × 1.2;decay 慢
    - bear: 启动值 = min(historical, forecast) × 0.8;decay 快
    """
```

### 6.6 β / WACC 算法

```python
def compute_company_wacc(
    industry_baseline_wacc: float,
    company_beta: float | None,   # 用 tushare get_history 算 60-day β vs 沪深 300
    debt_to_equity: float,         # 来自 balance_sheet
) -> float:
    """简化 CAPM:WACC = industry_baseline + β_adjustment + leverage_adjustment.

    - β_adjustment:(β - 1.0) × 0.02(每偏离 1 个 β 调 2%)
    - leverage_adjustment:debt_to_equity > 1.0 时 +1%(代理风险溢价)
    """
```

### 6.7 评估

- LoC ≈ 250(DCF helper + sensitivity + β 算法 + 增长率 3 场景)
- 测试:L0 ~15 case(包括缺数据 fallback)
- **关键设计原则**:LLM 只动**有信息源支撑**的假设(增长率 base 场景),不动**金融学公式锚定**的假设(WACC / terminal growth)

## § 7. 决策 Q5 — Cross-check 严重不一致:OutlierDiagnosisAgent

### 7.1 问题

4 模型(或 router 激活的 2-3 个)算出来,变异系数(CV)分 3 档:
- `consistent` (CV < 15%):正常
- `moderate` (15-30%):narrative 解释
- `severe` (>30%):**必须有显式诊断**

severe 时怎么处理?

### 7.2 Alternatives

| 选项 | 描述 | 优 | 缺 |
|---|---|---|---|
| **A. 后置 Critic + retry** | Critic 加 `valuation_consistency` scorer 评 Writer 是否 acknowledge;低分触发 writer retry | incremental,沿用现有 retry edge | **reactive** — Writer 可能掩饰,retry 1-2 轮才稳;LLM "模糊化"倾向真实存在 |
| **B. DataCollector 自愈** | severe 时回 DataCollector 多 fetch → 重算 | 数据层 self-heal | 修不到根因(数据没变,假设没变); latency 飘大 |
| **C. LLM OutlierDiagnosisAgent**(主选) | severe 时启动专门 LLM agent 诊断"哪个 lens 最 outlier + 为什么 + 我多大把握";Writer 必须引用 | **对应真研究员工作流**;算法层 explainability;与 Q3/Q4 范式一致 | 多 1 个 LLM call(severe 时才触发,not always)|

### 7.3 选择 C

行业 mindset:**severe divergence = signal, not bug**。真研究员遇到打架的反应是"哪个 lens 在告诉我没看见的事",**专门花时间诊断**,不是 retry / 找平均。

### 7.4 OutlierDiagnosisAgent 设计

**输入**:
- 4 (或 router 激活的子集) valuation 值
- 各模型的关键假设(DCF 的增长率 / WACC / 永续;PE 的可比公司均值)
- 公司基本面 narrative summary(来自 Analyst)
- 历史业绩趋势 5 年

**输出 schema**(新):
```python
class OutlierDiagnosis(BaseModel):
    model_config = ConfigDict(frozen=True)

    outlier_model: Literal["pe", "pb", "ev_ebitda", "dcf"]
    likely_cause: str = Field(max_length=300)  # 诊断假设错在哪
    confidence: Literal["high", "medium", "low"]
    recommended_action: Literal[
        "trust_consensus",        # 信另外几个 lens
        "flag_uncertainty",        # 报告里 flag 给用户决定
        "recompute_assumption",    # 调整假设重算(本 PR 不做,留 v1.x++)
    ]
    narrative: str = Field(max_length=500)  # 客户视角的解释,Writer 必须引用
```

**Writer 必须引用约束**(prompt):
- 若 `valuation_consistency == "severe"` 且 `outlier_diagnosis` not None:
  Writer narrative 第 X 段必须显式引用 `outlier_diagnosis.narrative`
- Critic `valuation_consistency` scorer 检查:narrative 是否引用了 diagnosis

### 7.5 失败处理

- OutlierDiagnosisAgent LLM call 失败:`outlier_diagnosis = None`,narrative flag "无法诊断打架原因,请人工 review"
- **不 retry**(避免 retry loop;diagnosis 不是 critical path)

### 7.6 评估

- LoC ≈ 150(agent + prompt + schema)
- 测试:L0 mock LLM ~5 case(consistent / moderate / severe 各 case);L2 cassette 加 1 个"DCF outlier" eval golden case

## § 9. Schema 改动

### 9.1 `ValuationAnalysis`(`backend/app/agents/investment_dd_schema.py`)

```python
class ValuationModel(str, Enum):
    PE = "pe"
    PB = "pb"
    EV_EBITDA = "ev_ebitda"
    DCF = "dcf"


class OutlierDiagnosis(BaseModel):
    model_config = ConfigDict(frozen=True)
    outlier_model: ValuationModel
    likely_cause: str = Field(max_length=300)
    confidence: Literal["high", "medium", "low"]
    recommended_action: Literal["trust_consensus", "flag_uncertainty", "recompute_assumption"]
    narrative: str = Field(max_length=500)


class ValuationAnalysis(BaseModel):
    # 现有字段保留 (pe_ratio / pe_historical_percentile / 等) — 向后兼容

    # 新增:router 信息
    industry_classification: str  # tushare industry_code 标准化
    active_models: list[ValuationModel] = Field(min_length=1, max_length=4)
    router_override_reasoning: str | None = Field(default=None, max_length=200)

    # 新增:4 模型估值结果(只有 active 模型有非空值)
    pe_value: float | None = None
    pb_value: float | None = None
    ev_ebitda_value: float | None = None
    dcf_base: float | None = None
    dcf_bull: float | None = None
    dcf_bear: float | None = None

    # 新增:DCF sensitivity 矩阵(5×5)
    dcf_sensitivity: list[list[float]] | None = None  # 5×5,(WACC ±1%/±2% × Terminal ±0.5%/±1%)

    # 新增:cross-check 结果
    valuation_consistency: Literal["consistent", "moderate", "severe"]
    outlier_diagnosis: OutlierDiagnosis | None = None  # 仅 severe 时填
```

### 9.2 Critic 新维度(`backend/app/agents/critic_subagents/`)

`backend/app/agents/critic_subagents/valuation_consistency.py` — 新 scorer:

## § 10. Error Handling

| 失败场景 | 处理 |
|---|---|
| Tushare API 限流 / 数据缺失字段 | helper raise `InsufficientDataForModel`(新 exception)→ 该 model 从 `active_models` 移除 → narrative 显式说明 |
| LLM router override 失败 | fallback deterministic baseline,trace 记录失败 |
| OutlierDiagnosisAgent LLM 失败 | `outlier_diagnosis = None`,narrative flag "无法诊断";**不 retry** |
| 所有 active models 都不能算(数据极差)| § 估值章节降级 "估值数据不足,跳过 cross-check";`valuation_consistency = None` 时 Critic scorer skip(不算 retry trigger)|
| `compute_company_wacc` 缺 β(get_history 失败)| fallback 行业 baseline wacc,trace 记录 |
| `compute_growth_trajectory` 缺历史(<3 年数据)| 使用行业 terminal_growth 作所有年增速,bull/bear 不展开,trace 记录 |

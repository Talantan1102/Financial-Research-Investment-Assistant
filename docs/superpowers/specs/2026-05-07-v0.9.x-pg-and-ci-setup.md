## § 1 决策摘要

### 决策 1:存量测试不动 + 新增"真 PG 护栏层"

**问题**:CI"全量挂 PG"语义有歧义 —— 是所有 L0/L1 都对真 PG,还是只 CI 永远启 PG service?

**业界 alternatives:**
- **全部测试切真 PG**:迁移成本高(`_patch_uuid_columns_to_string()` 等 sqlite hack 全部要清),CI 慢,改造收益为零
- **只新增护栏层**(本决策):存量 sqlite-override 测试保持快+隔离,新增 1 个 e2e test 加载完整 app_main + 真 PG → 覆盖 serve path
- **不挂 PG**(现状):/reports 测试用 sqlite,跟生产差异大,bug 漏到 dogfood 才暴露

**取舍**:只新增护栏层。

**理由:**
- L0/L1 sqlite-override 模式跑得快/隔离好,改造无收益(已经验证 router 逻辑正确)
- "CI 永远启 PG service" 的护栏价值在于 **新增的 e2e test 永远跑得起来**,不是把所有测试都拉慢
- 符合测试金字塔:L0 unit 快/多,L2 e2e 慢/少;护栏测试就 1 个,工程债最小

**含义:**
- 存量 L0/L1 测试**全部不动**(`test_reports_endpoints.py` / `test_user_isolation.py` 等保留 sqlite-override + UUID hack)
- 新增 `tests/e2e/test_pg_serve_path_e2e.py` —— 唯一一个加载 `app.app_main` + 用真 PG 的测试
- CI workflows 永远启 PG service container(其他测试用不到也不停)

### 决策 2:PG fixture 复刻 `milvus_test_container` 模式

**问题**:测试怎么连 PG?

**业界 alternatives:**
- **假定 PG 已外部启动**:本地能跑,GHA runner 没 docker compose 上下文会失败
- **session-scoped fixture 自动起容器**(本决策):测试自包含,本地+CI 行为一致
- **只用 GHA `services.postgres`**:CI 简单,但本地测试 fixture 还得另写,双轨

**取舍**:session-scoped fixture(自动起 + 自动拆 + 已起则复用)+ CI 同时启 GHA `services.postgres` 作 fallback。

**理由:**
- 已有 `milvus_test_container`(`backend/tests/conftest.py:140-172`)完全相同形态的成熟模板,抄过来改端口/healthcheck/image
- "外部已起则复用,自起则负责拆"的双模式逻辑已验证

### 决策 3:测试 PG 用独立数据库 `industry_assistant_test`

**问题**:测试和开发共享 `industry_assistant`?还是独立?

**取舍**:独立 test db。

**理由:**
- 共享会污染本地开发数据(测试 register 大量假 user,清理麻烦)
- `docker/init-db/` 已挂载 + 有 `01-init.sql` 在跑,新增 `00-create-test-db.sql`(字典序在前)创建 test db,工时 ~10 分钟
- 隔离让 fixture 末"truncate 所有表"安全,无副作用

### 决策 4:护栏 e2e test 用 `LLM_MODE=mock`

**问题**:e2e test 触发 research graph,LLM 怎么处理?

**取舍**:`LLM_MODE=mock`,不用 cassette。

**理由:**
- mock 跑得最快(无真 LLM 也无 cassette match)
- 这个测试目的是 **守护 serve path / DB / SSE**,不是验证研报内容,LLM 输出真假无所谓
- cassette 受 prompt drift 影响,会引入维护成本(每次 prompt 变就重录)

### 决策 5:不引 alembic,延后到 #3.5

**问题**:schema 演进用 `Base.metadata.create_all()` 还是 alembic?

**业界 alternatives:**
- **现在引入 alembic**:正经迁移工具,学院派最佳实践
- **`Base.metadata.create_all()` + 推后**(本决策):本 spec + v0.9.x 范围内只加表不改字段,够用
- **手写 SQL 在 init.sql 里**(legacy 现状):双轨 schema,长期负债

**取舍**:本 spec 范围用 `Base.metadata.create_all()`,DB 统一(roadmap #3.5)时一次性引入 alembic + 生成 baseline migration。

**理由:**
- v0.9.x 只加表(research_reports 已加),没改字段需求
- 现在引入 alembic 会让本 spec 工时翻倍,且 #3.5 还要重做(因为 #3.5 要把 trace_service / monitoring 的 sqlite 横切组件迁到 PG)
- 已知 issue:`docker/init-db/01-init.sql` 手写表 vs SQLAlchemy `Base.metadata` **是双轨 schema**,长期会漂移 —— 本 spec **不修这个**,在 § 4 明确,留给 #3.5

### Task 2:新增 `pg_test_container` session fixture

**文件:** `backend/tests/conftest.py`(在 `milvus_test_container` 旁边加)

**新增 helper:**
```python
def _wait_for_pg_ready(host: str, port: int, db: str, user: str, password: str, timeout: int = 60) -> None:
    """Poll PG via psycopg2 until accepting connections + db exists."""
    deadline = time.time() + timeout
    last_err: Exception | None = None
    while time.time() < deadline:
        try:
            import psycopg2
            conn = psycopg2.connect(host=host, port=port, dbname=db, user=user, password=password)
            conn.close()
            return
        except Exception as e:
            last_err = e
            time.sleep(2)
    raise TimeoutError(f"PG not ready after {timeout}s: {last_err}")
```

**新增 fixture:**
```python
@pytest.fixture(scope="session")
def pg_test_container() -> Iterator[dict[str, object]]:
    """Session-scoped PG container, mirrors milvus_test_container.

    若已外部启动(127.0.0.1:5432 listening + industry_assistant_test 可连),复用,
    session 末**不**清理。
    若没启动,fixture 自动 docker compose up -d postgres,session 末 down -v 清理。
    """
    repo_root = Path(__file__).resolve().parents[2]  # → repo root (where docker-compose.yml is)
    compose_file = repo_root / "docker-compose.yml"
    host = os.environ.get("POSTGRES_HOST", "127.0.0.1")
    port = int(os.environ.get("POSTGRES_PORT", "5432"))
    user = os.environ.get("POSTGRES_USER", "postgres")
    password = os.environ.get("POSTGRES_PASSWORD", "postgres123")
    test_db = "industry_assistant_test"

    started_by_us = False
    if not _is_port_listening(host, port):
        subprocess.run(
            ["docker", "compose", "-f", str(compose_file), "up", "-d", "postgres"],
            check=True,
        )
        started_by_us = True

    try:
        _wait_for_pg_ready(host, port, test_db, user, password, timeout=60)
        yield {
            "host": host, "port": port,
            "user": user, "password": password,
            "db": test_db,
            "url": f"postgresql://{user}:{password}@{host}:{port}/{test_db}",
        }
    finally:
        if started_by_us:
            subprocess.run(
                ["docker", "compose", "-f", str(compose_file), "down", "-v"],
                check=False,
            )
```

**Acceptance:**
- ✅ 本地 PG 已起时,fixture 复用不拆(repeatable test 不破坏外部状态)
- ✅ 本地 PG 未起时,fixture `docker compose up -d postgres` + session 末 `down -v`
- ✅ 调用方拿到 dict 含 `url`,可直接构造 SQLAlchemy engine

**工时:** 1.5 小时

### Task 3:新增 `test_pg_serve_path_e2e.py` 护栏测试

**新建文件:** `backend/tests/e2e/test_pg_serve_path_e2e.py`

**测试形态(伪代码):**

```python
"""Roadmap #2.5 护栏 — 唯一加载完整 app.app_main + 真 PG 的 e2e test.

覆盖 serve path:
1. app_main lifespan 真启动(包括 Base.metadata.create_all 在 test db 建表)
2. /auth/register 真插 user 表
3. POST /reports 真插 research_reports 表
4. SSE drain 收到 done,写回 report_json
5. GET /reports 用户隔离(alice 只看到自己的,bob 看到空列表)
"""

import pytest
from fastapi.testclient import TestClient


@pytest.mark.usefixtures("pg_test_container")
def test_register_post_sse_get_with_real_pg(pg_test_container, monkeypatch):
    # 1. 配 env 让 app_main 连 test db
    monkeypatch.setenv("POSTGRES_HOST", str(pg_test_container["host"]))
    monkeypatch.setenv("POSTGRES_PORT", str(pg_test_container["port"]))
    monkeypatch.setenv("POSTGRES_DB", str(pg_test_container["db"]))
    monkeypatch.setenv("LLM_MODE", "mock")

    # 2. 真 import app_main(serve path 真覆盖)
    # NOTE: app_main 在 import 时通过 database.py 的 module-level engine 读 env,
    #       所以 monkeypatch 必须在 import 前完成
    from app.app_main import app

    client = TestClient(app)

    # User A 注册
    r = client.post("/auth/register",
                    json={"username": "alice", "password": "alice123", "email": "a@a.com"})
    assert r.status_code in (200, 201)
    token_a = r.json()["access_token"]
    headers_a = {"Authorization": f"Bearer {token_a}"}

    # User A 发起报告
    r = client.post("/reports",
                    json={"target_name": "茅台", "target_ts_code": "600519.SH", "plan_id": "balanced"},
                    headers=headers_a)
    assert r.status_code == 201
    report_id = r.json()["id"]

    # User A 订阅 SSE,drain 完
    with client.stream("GET", f"/reports/{report_id}/stream", headers=headers_a) as resp:
        assert resp.status_code == 200
        for line in resp.iter_lines():
            if b"event: done" in line:
                break

    # User A 看到自己的列表
    r = client.get("/reports", headers=headers_a)
    assert r.status_code == 200
    assert any(item["id"] == report_id for item in r.json()["items"])

    # User B 注册 + 列表为空(数据隔离)
    r = client.post("/auth/register",
                    json={"username": "bob", "password": "bob123", "email": "b@b.com"})
    token_b = r.json()["access_token"]
    headers_b = {"Authorization": f"Bearer {token_b}"}

    r = client.get("/reports", headers=headers_b)
    assert r.status_code == 200
    assert r.json()["items"] == []

    # User B 看不到 A 的报告
    r = client.get(f"/reports/{report_id}", headers=headers_b)
    assert r.status_code in (403, 404)

    # tear-down: truncate test db tables 留给后续 run 干净
    # (放在 fixture 里更稳,见下方)
```

**Tear-down 策略:** 在 `pg_test_container` fixture 的 `try/finally` 里,session 末统一 truncate `users / research_reports` 表(若 fixture 自起容器则 down -v 已清,无需 truncate;若复用外部 PG 则 truncate 必要)。

**Acceptance:**
- ✅ 测试 `from app.app_main import app` 不报 ImportError(serve path 真覆盖)
- ✅ 6 个断言全部通过(注册 / POST / SSE / 列表 / 隔离-列表 / 隔离-详情)
- ✅ 后续 run 不被上一次状态污染

**工时:** 3 小时(含 SSE drain 边界 + tear-down 模板调试)

# 持仓总览(「整盘」视角)设计

> 来源:2026-06-12 brainstorm,起点是"从用户角度还有哪些场景没覆盖(如宏观/指数/板块)"。
> 结论:缺的不是"宏观/板块功能",是一个从未有过的视角——**把整个持仓当一个对象来看**。本 spec 定这个视角的边界、形态、要加的取数工具、以及调研背书。
> 配套调研:见本文末「调研依据」;完整带引用报告由 deep-research 跑出(103 agent / 24 条过对抗式核验)。

## 1. 为什么做这个 / 定位

把"用户想干的事(意图)× 看的是什么标的(数据域)"摊成矩阵后,一个事实跳出来:现有三根支柱(深度尽调 / 持仓监控 / 事件追踪)**全部钉在"个股 / 逐只持仓"这一列**——我们看市场永远是自下而上、从一只票出发。"板块 / 指数 / 大盘 / 宏观"这一整片自上而下、从市场出发的区域是空白。

但**空白 ≠ 都该填**。过我们一贯的"打不打得过 ChatGPT"尺子:"聊聊半导体怎么看 / 大盘会不会跌"是通用大模型主场(早已砍掉的"行业判断 / 术语解释"),捡回来等于稀释定位。能站住的只有**贴着"我们有、ChatGPT 没有"那几样**的刀:实时 A 股数据 + 用户本人的持仓 + 后台盯盘 + 跨会话记忆。

过完尺子,值得做的自上而下场景几乎**全部塌缩到同一个新增标的——「我的持仓组合」作为一个整体**。"宏观/指数/板块"在这里不是独立场景,是喂给这个整盘视角的**料**。

**归属决策:不另立支柱,合进"持仓监控"当它的「总览」层。** 持仓监控当前是"一只一只盯、有事推送"(自下而上、push);整盘是"打开先看整体"(自上而下、pull)。两者是总分关系——打开"我的持仓"先看整盘总览 → 点进某一只 → 那只的盯盘/异动就是现有的东西。这正补上持仓监控"一体两面(后台 daemon + 用户视角)"里一直缺的"用户视角总览"。

## 2. 范围:做什么 / 不做什么

整盘视角 = **一个引擎 + 两个看法**,不是三摊独立的活:

- **算账(组合归因)** —— 引擎。账户今天/某区间为啥涨跌,把这笔账拆给:跟大盘、板块超额、个股特质、各大类资产。是最硬、最是 ChatGPT 给不了、最有技术深度的一刀。
- **看结构(配置与集中度)** —— 算账的中间数据顺手一摆:钱按大类分在哪、股票部分压在哪些板块、跨品种真实暴露。
- **复盘(走势回看)** —— 把每天的账存下来,串成时间线:整盘 vs 沪深300,可选 近1月/近3月/近半年/近1年/近3年。

**明确不做(守克制 + 守红线):**

- ❌ **买卖 / 调仓建议**("要不要减仓""该不该补")——合规红线,呼应本项目 deep-research "no-recommendation" 立场,不碰。
- ❌ **大盘 / 板块"怎么看、会不会跌"的择时判断**——ChatGPT 主场 + 不做择时,容易变成瞎指挥。
- ❌ **术语解释 / 行业判断**——早已显式砍。
- ❌ **大事提前提醒**(出数据/财报到点提醒)——是独立的"事件追踪"支柱,**另立**,不塞进整盘搅一块。
- ❌ **逐持仓精确收益率归因**(每只票时间加权收益率贡献)——连富达都白纸黑字不做(`position-level performance`),我们只到"哪几只拖累最大"的粗粒度。
- ❌ **按因子归因**——消费级几乎无人做(连 Sharesight 都只到板块/行业/收益来源),砍。
- ❌ **基金深度穿透**——看不穿,只做诚实表达(见 §3、§4),轻穿透留口子。

## 3. 数据现实与关键约束(决定设计形状)

**(a) 只有持仓快照,没有资金流水。** 与用户对齐:本产品不托管真钱,用户手动录入/导入持仓,我们看不到充提记录。

- 行业标准的"账户为什么涨跌"第一刀是"现金流(你存取的钱) vs 投资盈亏"(富达),**对我们不适用**——我们天生就在"投资盈亏"那一侧。
- 这反而把定位顶上去:富达做"现金流 vs 盈亏"那层、**但不往下拆板块**;我们跳过看不到的那层,直接做"盈亏为什么"——也就是**连富达都不做的板块拆解**。漏的是上面那层(本就看不到),做的是下面更深、更有讲头那层。
- **当日算账**:当天持仓不变 → 干净,直接拆,不需要现金流。
- **复盘(跨日)**:用户中途会加减仓 → "账户涨了"不等于"票牛了"。必须用**剔除加减仓影响的链式日收益(time-weighted)**:每天用当天的持仓算当天纯市场涨跌,再串起来。需要**每日持久化一张持仓快照**(盯盘 daemon 顺手存)。这个"剔除资金影响"正是行业里更讲究的收益率口径,是核心技术深度点之一。

**(b) 多资产,不只股票。** 用户也买基金/债/黄金/现金等。

- 看结构先按**大类**分(股票 / 场内 ETF / 场外基金 / 债基 / 黄金 / 现金),股票部分再往下拆板块。
- 算账在整盘层按"每个产品涨跌"分摊永远成立;"深拆到大盘/板块"这刀**只对股票部分**成立。基金里:宽基 ETF(如 300ETF)≈对应指数;主动基金只看整体净值涨跌。

**(c) 基金看不穿底层,且有法定滞后。** 中国公募只季度披露前十大重仓股(季末后 15 工作日)、半年报/年报才全披露;美国季度持仓最多滞后 60 天;还有季末"橱窗粉饰"。

- 因此"**老实承认看不穿基金 / 标注数据 as-of 披露日 + 可能已变动**"是**有法规依据的诚实设计,不是能力短板**。穿透展示(若做)绝不能暗示精确实时。

## 4. 三件事的设计

### 4.1 算账(组合归因)—— 后端确定性计算,LLM 只讲人话

**这是全项目最该讲的分界:取数是工具、算账是确定性计算、讲人话才是 LLM。**

- **取数(工具,确定性,连 tushare)**:每只持仓当日收益、所属大类/板块、沪深300 当日、相关行业指数当日、基金当日净值。见 §6。
- **算账(后端确定性计算,不交给 LLM —— 让大模型算数它会编)**:
  1. 组合当日收益 = Σ(各持仓权重 × 当日收益);先按大类分摊出各大类贡献。
  2. 股票部分三层拆解:**跟大盘** = 股票仓权重 × 大盘当日收益(MVP 取 beta≈1,**不逐只估 beta**避免过度工程;beta 偏差自然落进"个股特质"残差);**板块超额** = Σ(各板块权重 ×(板块当日 − 大盘当日));**个股特质** = 残差。三层加总须精确等于股票部分收益(闭合,可单测)。
  3. 基金部分:宽基 ETF 归到对应指数;主动基金只给产品级涨跌 + "看不穿"标注。
- **LLM 的活(且仅此)**:从算好的数里**挑该说的一两件**(不是把 20 只票念一遍)、**翻成人话**、**接上 persona/记忆**(如"记得你念叨白酒压太重")。断言层面:LLM 不参与算数、不给买卖建议、对看不穿的基金如实说看不穿。

### 4.2 看结构(配置与集中度)

- 大类饼图(M1 招牌饼图范式)+ 股票部分板块条。
- **跨品种真实暴露**:把"白酒股 + 白酒主题基金"合并计,给出"白酒占总身家约 30%"这种**只有整盘角度才看得见**的集中度。
- 按大类/板块的"你压得比大盘重/轻"提示(蚂蚁财富按风险大类诊断范式)。基金大类拆解标 as-of 季报日。

### 4.3 复盘(走势回看)

- 整盘 vs 沪深300 折线,时间区间可选 **近1月/近3月/近半年/近1年/近3年**(业界惯例:雪球/天天基金/Robinhood)。切区间 → 百分比与对比线跟着换;**区间内整体跌 → 线转绿**(红涨绿跌,与单日一致)。
- 口径:剔除加减仓的链式日收益(§3a),展示文案点明"已剔除你的加减仓、只串纯市场涨跌,跟大盘比才公平"。

## 5. 信息架构与视觉(调研背书)

- **卡片 + 下钻**:整盘总览是几张摘要卡片竖排,点进去看详情;不堆一张密集大表(Empower 范式)。
- **头条 = 总身家大数字 + 多时间口径**:首屏头条放"总身家"净值,同时给"今天"与"今年/拉长看"两个时间口径(Empower/富达范式),不只当天。
- **下钻出口**:点任意持仓 → 它的逐只盯盘详情(= 现有持仓监控逐只能力),体现总分关系。
- **涨跌配色硬约束**:**中国红涨绿跌**,与西方完全相反且经实验证实是文化习得。参考 Robinhood/富达等西方标杆配色时**必须本地化反转**——这是反模式防范点。
- **诚实标注**:看不穿的基金、滞后的季报数据,都带 as-of 日期 + "可能已变"提示。
- 视觉方向:本页先走 iOS 干净风(系统字、浅灰底白圆角卡、分段控件、饼图)。全 App 是否统一成 iOS 风见 §9 开放问题。

## 6. 要新增的取数工具(及"取数 vs 算账"分界)

落地需要补的工具(几乎全是"取数"类,现有工具几乎全是个股维度):

1. **持仓数据模型扩展**:每条持仓带「资产类型」(股票/场内基金/场外基金/债/黄金/现金)+ 代码,不止股票。
2. **取基金**:类型 + 每日净值(对应 tushare `fund_basic` / `fund_nav`)——算基金涨跌、归大类。
3. **取指数当日**:沪深300 等(`index_daily` / `index_dailybasic`)——算账"跟大盘"那刀。
4. **取板块/行业当日**:行业指数当日收益 + 个股行业归属(申万行业 / `stock_basic` 行业字段)——板块拆解。
5. **(留口子)基金季报持仓**:`fund_portfolio`(季度、需较高积分)——给 §7 轻穿透用。

**分界(项目可讲性重点)**:该加的是"取数的工具"(确定性、连数据源),不是"加一个会算账的 AI";"算账"是后端确定性计算;LLM 只讲人话。这些取数工具不止整盘用——聊天里直接问"沪深300今天多少""白酒板块咋样""我那只基金涨没涨"也全靠它们,等于顺手补上"市场/基金"这块一直缺的数据底座。

## 7. 留的口子(以后做,先别做)

- **轻穿透基金**:用基金季报前十大 + 类型/主题标签做粗穿透(标 as-of 季报日 + 可能已变),广发"全市场基金账本"是先例。先"看不穿+老实说",留口子。
- **大事提醒**(事件追踪支柱):宏观/财报日历到点提醒相关持仓——独立做。
- **资金流水接入**:以后接券商或手动记账,则启用"现金流 vs 投资盈亏"那一刀。
- **每日推送**:daemon 收盘后推"今日整盘小结"(现在是 pull 页面)。

## 8. 测试要点

- **算账确定性单测**:给定持仓 + 行情,三层拆解加总精确等于股票部分收益、各大类分摊加总等于组合收益(数值精确,不依赖 LLM)。
- **复盘链式日收益**:构造加减仓场景,验证 time-weighted 正确剔除资金影响。
- **多资产 + 快照持久化**:每日持仓快照写入与回读;多资产分类正确。
- **LLM 叙事走 cassette**:断言只挑重点+人话+记忆注入,且**不算数、不荐股、看不穿基金如实标注**。
- **前端**:红涨绿跌颜色断言;基金/季报数据展示 as-of 日 + "可能已变"提示存在。

## 9. 开放问题

- 全 App 是否统一成 iOS 风(本页先 iOS);现有前端是"安静工坊"衬线风,要不要一起翻。
- 复盘默认区间(近1月 / 近3月 / 近1年)。
- 国内产品(雪球 / 同花顺 / 天天基金 / 富途 / 券商 APP)的整盘多资产总览**一手形态本轮调研未覆盖**(只深挖了 Empower/富达/广发/M1/蚂蚁),落地前可补截图调研。
- 持仓数据来源:手动录入 vs 截图导入 OCR(广发那种体验,但是大工程,先手动/seed)。
- 当前 chat 是匿名 stub(`user_id=anonymous`),整盘需要真 user_id 绑持仓——与现有持仓监控的 user 模型对齐。

## 10. 调研依据(过对抗式核验)

- **IA = 卡片+下钻、头条=净值+多时间口径**:Empower 官方支持文档(Home>Overview widgets + 内嵌下钻;Net Worth 头条同时显示 365 天与 1 天)。<https://support-personalwealth.empower.com/hc/en-us/articles/201169740-Dashboard-Overview>
- **"账户为什么涨跌"标准机器 = 现金流 vs 盈亏 + 双收益率**(我们因无流水只取后半):富达帮助页 `What drove your change in balance?` + money-weighted/time-weighted。<https://www.fidelity.com/webcontent/ap002390-mlo-content/19.09/help/learn_performancereporting.shtml>
- **多轴归因是真做的进阶能力、但非因子归因**:Sharesight Contribution Analysis;富达 Portfolio Analysis 对基金 look-through 按资产类别/行业/境内外拆。<https://www.sharesight.com/blog/explore-your-portfolio-performance-with-the-contribution-analysis-report/> · <https://www.fidelity.com/products/funds/content/analyze.shtml>
- **逐持仓收益率归因连富达都不做** → 克制有据:同富达帮助页。
- **看不穿基金有法规依据 + 季度滞后 + 橱窗粉饰**:CSRC《公开募集证券投资基金信息披露管理办法》;SEC final rule 33-8393;Harvard Law window dressing(Agarwal/Gay/Ling 2014)。穿透先例:广发基金 APP 8.0「全市场基金账本」。<https://www.sec.gov/rules/2004/02/shareholder-reports-and-quarterly-portfolio-disclosure-registered-management> · <https://corpgov.law.harvard.edu/2014/09/17/window-dressing-in-mutual-funds/> · <https://www.chnfund.com/article/ARcde2d453-0333-cf17-2c7b-3a145822b0b0>
- **结构三件套 = 大类分区 + 饼图 + 超配提示**:广发 5 大资产专区 / M1 Pie / 蚂蚁财富风险大类诊断。<https://www.optimizedportfolio.com/m1-finance-vs-wealthfront/> · <https://www.woshipm.com/pd/5829101.html>
- **红涨绿跌是文化习得、不可照搬西方**:Hsee/Jiang et al., *Up or Down: How Culture and Color Affect Judgments* (JBDM 2014)。<https://www.researchgate.net/publication/256252646_Up_or_Down_How_Culture_and_Color_Affect_Judgments>
- **反模式提醒**:Sharesight 不是 Brinson 式"选股 vs 配置"归因(该 claim 被核验否决),而是按收益来源/多轴分组——设计时勿混淆两种"归因"。

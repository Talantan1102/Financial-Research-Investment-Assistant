# Seed 构造设计方案 v4.0 - LLM 动态生成版

**编写日期**: 2026-03-24  
**版本**: v4.0  
**编写人**: 卤蛋 🐤  
**更新说明**: 采用 LLM 动态生成替代模板生成，解决模板覆盖不足问题

---

## 1. 背景与问题

### 1.1 旧方案（v1.0-v3.3）的问题

| 问题 | 说明 |
|------|------|
| **模板覆盖不足** | 105,560种理论槽位组合，实际模板仅覆盖约5% |
| **生成重复率高** | 大量组合 fallback 到兜底模板，内容重复 |
| **自然度不足** | 机器味重，不像真实用户提问 |
| **维护成本高** | 每增加一个槽位值，需编写大量新模板 |

### 1.2 新方案（v4.0）的优势

| 优势 | 说明 |
|------|------|
| **100%覆盖** | 任意槽位组合都能生成内容 |
| **自然度高** | 接近真实用户表达方式 |
| **零维护成本** | 新增槽位自动适配，无需写模板 |
| **无限扩展** | 同一组合可多次采样生成不同变体 |

## 2. LLM 动态生成方案

### 2.1 核心思想

```
槽位组合 + LLM → 自然语言问题
```

不再手写模板，而是让 LLM（qwen-max）根据槽位信息实时生成问题。

### 2.2 技术架构

```
┌─────────────────────────────────────────────────────────────┐
│  Slot Selector                                              │
│  ├─ 用户类型 (7种)                                           │
│  ├─ 意图 (7种)                                               │
│  ├─ 场景 (5种)                                               │
│  ├─ 风格 (4种)                                               │
│  └─ 实体选择器 (0-3个股票/行业/概念)                          │
└──────────────────────┬──────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  Prompt Builder                                             │
│  ├─ 用户画像描述 (知识水平、表达风格)                         │
│  ├─ 意图描述 (想做什么)                                       │
│  ├─ 场景描述 (情绪、持仓状态)                                 │
│  ├─ 风格指令 (直接问/带背景/情绪化/专业范)                    │
│  ├─ 实体描述 (涉及的股票/行业/概念)                           │
│  └─ 核心约束 (禁止编造市场事实)                               │
└──────────────────────┬──────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  LLM (qwen-max)                                             │
│  ├─ 输入: 结构化 prompt                                     │
│  ├─ 处理: 理解槽位，生成自然语言                             │
│  └─ 输出: 投资咨询问题                                       │
└──────────────────────┬──────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  Seed Output                                                │
│  ├─ content: 问题文本                                        │
│  ├─ slots: 槽位信息                                          │
│  ├─ entities: 实体信息                                       │
│  └─ tags: 标签 (复杂度、技能等)                               │
└─────────────────────────────────────────────────────────────┘
```

## 3. 槽位定义

### 3.1 基础槽位

| 槽位 | 可选值 | 说明 |
|------|--------|------|
| **user_type** | 小白、散户、价值投资者、技术派、专业、机构、基金经理 | 用户画像 |
| **intent** | 查价格、问估值、问买卖、比股票、问风险、学知识、深度分析 | 意图 |
| **context** | 空仓观望、已盈利、已亏损、深套中、准备买入 | 场景/情绪 |
| **style** | 直接问、带背景、情绪化、专业范 | 表达风格 |

**理论组合数: 7 × 7 × 5 × 4 = 980 种**

### 3.2 实体槽位（灵活）

| 类型 | 数量 | 示例 |
|------|------|------|
| **股票** | 0-3只 | 贵州茅台、宁德时代、比亚迪 |
| **行业** | 0-2个 | 白酒、新能源、银行 |
| **概念** | 0-2个 | ROE、PE、MACD |

**实体组合数: 约 10 种（0个/1股/2股/3股/1行业/2行业/1概念/混合等）**

### 3.3 总组合数

```
基础组合: 980 种
× 实体组合: ~10 种
= 约 10,000 种有效组合
```

## 4. Prompt 设计

### 4.1 核心要求（防幻觉）

**禁止编造市场事实**:
- ❌ 禁止描述涨跌走势（"一直跌"、"涨得好"）
- ❌ 禁止询问市场状况（"最近怎么样"）
- ❌ 禁止价格预测（"还能涨吗"）

**允许表达的内容**:
- ✅ 用户持仓状态（"套了20%"、"已经盈利"）
- ✅ 用户情绪（"急死了"、"很高兴"）
- ✅ 投资意图（"想买入"、"问估值"）

### 4.2 Prompt 模板

```python
GENERATION_PROMPT = """
你是一个专业的金融投资用户模拟器。请根据以下信息生成一个自然的投资咨询问题。

【重要要求 - 必须遵守】
1. ✅ 可以表达用户的情绪（如"担心"、"高兴"、"焦虑"）
2. ✅ 可以提及用户的持仓状态（如"套了20%"、"已经盈利"）- 这是用户输入的事实
3. ❌ 禁止描述具体的涨跌走势（如"一直跌"、"涨得挺好"、"最近走势如何"）
4. ❌ 禁止编造市场价格或市场状况
5. 只表达用户的意图和困惑，不涉及对市场的判断

【用户画像】
- 用户类型：{user_type}
- 投资知识水平：{knowledge_level}
- 典型表达风格：{expression_style}

【提问意图】
- 意图：{intent}
- 想了解的内容：{intent_description}

【当前场景】
- 场景：{context}
- 情绪状态：{emotion}
- 持仓情况：{position_status}

【表达风格要求】
- 风格：{style}
{style_instruction}

【涉及的实体】
{entities_description}

【生成示例】

❌ 错误示例（编造市场事实）：
- "比亚迪一直跌，我该怎么办？"（编造"一直跌"）
- "茅台涨得真好，还能买吗？"（编造"涨得好"）

✅ 正确示例（只表意图+持仓事实）：
- "我持有的比亚迪套了20%，好担心，该不该割肉？"
- "我持有的茅台已经盈利不少了，现在还能加仓吗？"
- "我想建仓银行股，需要分析哪些指标？"
- "ROE是什么意思？怎么看？"

请生成符合要求的问题：
"""
```

## 9. 决策建议

### 9.1 何时使用 LLM 方案

✅ **推荐使用**:
- 需要大规模多样化 Seed（>1000）
- 追求自然度，接近真实用户
- 槽位经常变化，需要灵活扩展
- 有足够 API 预算

### 9.2 何时使用模板方案

✅ **仍可使用**:
- 小规模实验（<500）
- 对生成速度要求高
- 无 API 访问条件
- 需要严格控制生成内容

### 9.3 混合方案（推荐）

```
小规模验证 → 模板方案（快速）
大规模生产 → LLM方案（高质量）
```

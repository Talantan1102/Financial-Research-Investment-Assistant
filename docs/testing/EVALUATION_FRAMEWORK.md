## 1. 概述

### 1.1 评估目标

建立研投助手的标准化评估体系，覆盖以下核心能力：

1. **检索能力**：评估模型从财报/研报中提取和推理信息的能力，作为 GRPO 训练前的基线
2. **研究质量**：评估 DeepResearch 生成研报的分析深度和专业性
3. **系统性能**：评估响应速度、计算成本和并发处理能力

### 1.2 适用范围

| 评估对象 | 说明 |
|---------|------|
| 基础模型（qwen-max） | GRPO 训练前的基线评估 |
| 训练后模型 | GRPO 训练后的能力评估 |
| DeepResearch 系统 | 多 Agent 协作的研报生成质量 |
| MCP 工具链 | 17 个工具的端到端调用性能 |

### 1.3 评估原则

- **可量化**：优先使用可自动计算的指标，减少主观评分
- **可复现**：固定评估数据集和计算方式，确保结果可复现
- **分层递进**：从单工具 → 多工具组合 → 完整研报，逐层评估
- **训练对齐**：评估指标与 GRPO 奖励函数保持一致

## 2. 检索能力评估（GRPO 训练基础）

本节定义 6 类检索任务的评估指标，用于建立 GRPO 训练前的基线，并作为训练后的对比参照。

### 2.1 定量检索

**任务描述**：从财报/研报中提取具体数值信息（如营收、净利润、EPS 等）。

| 指标 | 计算方式 | 目标值 |
|------|---------|--------|
| **准确率 (Precision)** | 正确提取数 / 模型提取总数 | ≥ 85% |
| **召回率 (Recall)** | 正确提取数 / 应提取总数 | ≥ 80% |

**评估数据集要求**：
- 样本量：≥ 100 条
- 覆盖：利润表、资产负债表、现金流量表的关键字段
- 标注：每条样本需标注 ground truth 数值

**示例用例**：

```
问题：贵州茅台 2024 年 Q3 的营业收入是多少？
期望：从 get_financial_report 返回中提取正确的营收数值
评估：提取的数值 vs ground truth 数值（容差 ±0.1%）
```

### 2.2 定性检索

**任务描述**：总结非数值信息、提取观点和判断（如管理层展望、行业分析结论）。

| 指标 | 计算方式 | 目标值 |
|------|---------|--------|
| **F1 分数** | 2 × (P × R) / (P + R)，基于关键信息点 | ≥ 0.75 |
| **一致性 (Consistency)** | 多次回答的关键观点一致比例 | ≥ 90% |

**评估数据集要求**：
- 样本量：≥ 80 条
- 类型：管理层评述总结、风险提示归纳、业务亮点提取
- 标注：每条样本标注关键信息点列表

**示例用例**：

```
问题：总结茅台最新财报中管理层对未来的展望
期望：提取"产能扩张"、"国际化战略"、"数字化转型"等关键点
评估：模型输出关键点 vs 标注关键点的 F1 分数
```

### 2.3 数值推理

**任务描述**：基于提取的财务数据进行计算（如增长率、财务比率等）。

| 指标 | 计算方式 | 目标值 |
|------|---------|--------|
| **计算准确率** | 计算结果正确数 / 总计算数 | ≥ 90% |

**计算准确性判定规则**：

| 计算类型 | 容差范围 | 示例 |
|---------|---------|------|
| 百分比计算（ROE、增长率） | ±0.5% | ROE = 20.5% ± 0.5% |
| 绝对值计算（市值、总资产） | ±1% | 市值 = 2.3 万亿 ± 1% |
| 排名/比较 | 精确匹配 | "茅台 ROE 高于平均" |

**评估数据集要求**：
- 样本量：≥ 60 条
- 覆盖：ROE/ROA 计算、同比/环比增长率、市盈率/市净率
- 标注：每条标注计算过程和正确结果

**示例用例**：

```
问题：计算茅台最近 4 个季度的 ROE 变化趋势
期望：正确计算每个季度的 ROE = 净利润 / 净资产
评估：每个季度的计算结果 vs ground truth（容差 ±0.5%）
```

### 2.4 复杂检索

**任务描述**：需要跨多个文档/数据源综合信息的检索任务。

| 指标 | 计算方式 | 目标值 |
|------|---------|--------|
| **信息完整度** | 覆盖信息源数 / 应覆盖信息源数 | ≥ 75% |

**信息完整度分级**：

| 等级 | 分数 | 描述 |
|------|------|------|
| 完整 | 1.0 | 覆盖所有必需信息源 |
| 基本完整 | 0.75 | 覆盖 75% 以上信息源 |
| 部分完整 | 0.5 | 覆盖 50%-75% 信息源 |
| 不完整 | 0.25 | 覆盖不足 50% |

**评估数据集要求**：
- 样本量：≥ 50 条
- 类型：跨 Skill 综合查询（如行情 + 财务 + 风险）
- 标注：每条标注需要调用的工具清单和综合信息要点

**示例用例**：

```
问题：全面分析茅台的投资价值
期望工具链：get_quote → get_financial_report → calculate_financial_ratios → calculate_risk_metrics
评估：检查是否覆盖了行情、财务、风险三个维度的信息
```

### 2.5 财务建模

**任务描述**：复杂的估值计算和财务模型构建。

| 指标 | 计算方式 | 目标值 |
|------|---------|--------|
| **模型准确性** | 加权评分（公式正确性 × 0.4 + 输入准确性 × 0.3 + 结论合理性 × 0.3） | ≥ 0.70 |

**评估维度细分**：

| 子维度 | 权重 | 评估方式 |
|--------|------|---------|
| 公式选择正确性 | 40% | 规则匹配（DCF/PE/PB 公式是否正确） |
| 输入数据准确性 | 30% | 与 ground truth 数值比对 |
| 结论合理性 | 30% | LLM 评判（结论是否与输入数据一致） |

**评估数据集要求**：
- 样本量：≥ 30 条
- 类型：DCF 估值、相对估值（PE/PB）、盈利预测
- 标注：标注正确的估值模型、输入参数和合理结论范围

**示例用例**：

```
问题：用 DCF 模型估算茅台的合理估值
期望：正确选择自由现金流折现公式，使用合理的折现率和增长率假设
评估：公式正确 + 输入数据来源可靠 + 结论在合理范围内
```

### 2.6 市场分析

**任务描述**：竞争分析、因果推理等高层次分析任务。

| 指标 | 计算方式 | 目标值 |
|------|---------|--------|
| **分析深度评分** | LLM 评判 + 规则评分的加权平均 | ≥ 3.5/5.0 |

**评分标准**（5 分制）：

| 分数 | 描述 |
|------|------|
| 5 | 深入全面：多维度分析，因果链条完整，有独到见解 |
| 4 | 较好：覆盖主要维度，逻辑清晰，有数据支撑 |
| 3 | 合格：基本覆盖要点，但分析较浅 |
| 2 | 不足：遗漏重要维度，逻辑有缺陷 |
| 1 | 差：分析片面或有明显错误 |

**评估数据集要求**：
- 样本量：≥ 40 条
- 类型：行业竞争格局分析、宏观因素影响推理、投资逻辑论证
- 标注：标注分析应覆盖的维度和关键论点

**示例用例**：

```
问题：分析白酒行业的竞争格局，茅台的护城河在哪里？
期望维度：品牌力、定价权、渠道、产能、消费升级趋势、竞争对手对比
评估：覆盖维度数 + 论证逻辑性 + 数据支撑度
```

### 2.7 检索能力评估汇总

| 任务类型 | 核心指标 | 目标值 | 样本量 | 自动化程度 |
|---------|---------|--------|--------|-----------|
| 定量检索 | 准确率 + 召回率 | P≥85%, R≥80% | ≥100 | 全自动 |
| 定性检索 | F1 + 一致性 | F1≥0.75, C≥90% | ≥80 | 半自动 |
| 数值推理 | 计算准确率 | ≥90% | ≥60 | 全自动 |
| 复杂检索 | 信息完整度 | ≥75% | ≥50 | 半自动 |
| 财务建模 | 模型准确性 | ≥0.70 | ≥30 | 半自动 |
| 市场分析 | 分析深度评分 | ≥3.5/5.0 | ≥40 | LLM 评判 |

**总评估样本量**：≥ 360 条

## 3. DeepResearch 研究质量评估

基于 FinResearchBench 逻辑树评估方法论，对 DeepResearch 生成的研报进行结构化质量评估。

### 3.1 规则推导指标（量化）

这些指标可通过解析研报结构自动计算，无需人工介入。

#### 3.1.1 分析广度

**定义**：逻辑树中每个节点的平均子节点数，反映分析的覆盖面。

```
分析广度 = Σ(每个非叶子节点的子节点数) / 非叶子节点总数
```

| 等级 | 分值范围 | 描述 |
|------|---------|------|
| 优秀 | ≥ 3.5 | 每个分析点平均展开 3.5+ 个子维度 |
| 良好 | 2.5-3.5 | 覆盖面较好 |
| 合格 | 1.5-2.5 | 覆盖面一般 |
| 不足 | < 1.5 | 分析维度单一 |

#### 3.1.2 分析深度

**定义**：逻辑树的纵向深度，反映分析的层次性。

```
分析深度 = 最大深度 × 叶子节点平均深度
```

| 等级 | 分值范围 | 描述 |
|------|---------|------|
| 优秀 | ≥ 12 | 深入多层分析（如 最大深度 4 × 平均深度 3） |
| 良好 | 8-12 | 分析有层次 |
| 合格 | 4-8 | 基本分析 |
| 不足 | < 4 | 分析浅层 |

#### 3.1.3 信息密度

**定义**：逻辑树中信息含量的综合度量。

```
信息密度 = 总节点数 × 证据节点占比
```

其中**证据节点**是指包含具体数据、引用或事实支撑的节点。

| 等级 | 分值范围 | 描述 |
|------|---------|------|
| 优秀 | ≥ 30 | 信息丰富且有据可查（如 50 节点 × 60% 证据） |
| 良好 | 15-30 | 信息较充实 |
| 合格 | 8-15 | 基本信息覆盖 |
| 不足 | < 8 | 信息匮乏 |

#### 3.1.4 段落丰富度

**定义**：研报正文中每个副标题下的平均字数，反映论述的充实程度。

```
段落丰富度 = 正文总字数 / 副标题数量
```

| 等级 | 分值范围 | 描述 |
|------|---------|------|
| 优秀 | ≥ 500 字/节 | 论述充分详实 |
| 良好 | 300-500 字/节 | 论述较完整 |
| 合格 | 150-300 字/节 | 论述基本 |
| 不足 | < 150 字/节 | 论述过于简略 |

#### 3.1.5 规则指标汇总

| 指标 | 计算公式 | 优秀阈值 | 自动化 |
|------|---------|---------|--------|
| 分析广度 | avg(子节点数) | ≥ 3.5 | 可自动 |
| 分析深度 | max_depth × avg_leaf_depth | ≥ 12 | 可自动 |
| 信息密度 | 总节点 × 证据占比 | ≥ 30 | 可自动 |
| 段落丰富度 | 总字数 / 副标题数 | ≥ 500 | 可自动 |

### 3.2 LLM 评估指标（定性）

以下指标需要通过 LLM（如 GPT-4 / qwen-max）进行评判，采用 5 分制评分。

#### 3.2.1 分析框架质量

**评估要点**：研报是否采用了合理的分析框架（如 SWOT、波特五力、PEST 等）。

| 分数 | 描述 |
|------|------|
| 5 | 框架选择精准，维度全面，层次分明 |
| 4 | 框架合理，覆盖主要维度 |
| 3 | 有基本框架，但不够全面 |
| 2 | 框架选择不当或维度缺失 |
| 1 | 无明确分析框架 |

#### 3.2.2 逻辑一致性

**评估要点**：分析过程中的论证是否前后一致，结论是否与论据匹配。

| 分数 | 描述 |
|------|------|
| 5 | 全文逻辑严密，论据充分支撑结论 |
| 4 | 整体逻辑清晰，偶有小瑕疵 |
| 3 | 基本逻辑通顺，部分论证薄弱 |
| 2 | 存在逻辑矛盾或跳跃 |
| 1 | 逻辑混乱，结论与论据脱节 |

#### 3.2.3 观点清晰度

**评估要点**：核心观点是否明确、有区分度，投资建议是否清晰。

| 分数 | 描述 |
|------|------|
| 5 | 观点鲜明，论证充分，有独到见解 |
| 4 | 观点明确，有数据支撑 |
| 3 | 观点基本清晰，但缺乏力度 |
| 2 | 观点模糊，缺乏明确立场 |
| 1 | 无明确观点，泛泛而谈 |

#### 3.2.4 表达专业性

**评估要点**：是否使用专业金融术语，表述是否符合研报规范。

| 分数 | 描述 |
|------|------|
| 5 | 完全符合专业研报标准，术语准确 |
| 4 | 专业性较好，偶有口语化表述 |
| 3 | 基本专业，部分表述不够规范 |
| 2 | 专业性不足，多处表述不当 |
| 1 | 非专业表述，不像研报 |

#### 3.2.5 表达连贯性

**评估要点**：段落之间的衔接是否自然，全文是否有统一的叙述逻辑。

| 分数 | 描述 |
|------|------|
| 5 | 行文流畅，段落衔接自然 |
| 4 | 整体连贯，少数过渡生硬 |
| 3 | 基本连贯，部分段落衔接不当 |
| 2 | 多处断裂，读起来跳跃 |
| 1 | 内容碎片化，缺乏连贯性 |

#### 3.2.6 视觉-语言协同

**评估要点**：文字描述与数据图表是否相互呼应，是否有效利用可视化辅助分析。

| 分数 | 描述 |
|------|------|
| 5 | 图文配合紧密，可视化增强理解 |
| 4 | 有图表支撑，基本与文字对应 |
| 3 | 有少量图表，但关联不紧密 |
| 2 | 图表与文字脱节 |
| 1 | 无可视化支撑或完全不相关 |

#### 3.2.7 LLM 评估指标汇总

| 指标 | 评分方式 | 目标分 | 评估者 |
|------|---------|--------|--------|
| 分析框架质量 | 5 分制 | ≥ 3.5 | LLM |
| 逻辑一致性 | 5 分制 | ≥ 4.0 | LLM |
| 观点清晰度 | 5 分制 | ≥ 3.5 | LLM |
| 表达专业性 | 5 分制 | ≥ 4.0 | LLM |
| 表达连贯性 | 5 分制 | ≥ 4.0 | LLM |
| 视觉-语言协同 | 5 分制 | ≥ 3.0 | LLM |

**综合评分**：

```
DeepResearch 质量分 = (框架 × 0.20 + 逻辑 × 0.20 + 观点 × 0.15 + 专业性 × 0.20 + 连贯性 × 0.15 + 视觉协同 × 0.10)
```

## 4. 性能评估

### 4.1 响应速度

#### 4.1.1 普通提问响应时间

**定义**：从用户发送问题到收到完整回答的端到端耗时。

| 场景 | 目标值 | 测量方式 |
|------|--------|---------|
| 简单查询（单工具） | ≤ 3s | P95 延迟 |
| 中等分析（2-4 工具） | ≤ 8s | P95 延迟 |
| 复杂分析（4+ 工具） | ≤ 15s | P95 延迟 |

**耗时分解**：

```
总耗时 = Skill 选择耗时 + 工具 Schema 加载耗时 + 工具执行耗时 + LLM 生成耗时
```

| 阶段 | 目标值 |
|------|--------|
| Round 1: Skill 选择（LLM） | ≤ 1.5s |
| Round 2: 工具调用计划（LLM） | ≤ 2.0s |
| Round 2: MCP 工具执行 | ≤ 3.0s（单工具） |
| Round 3: 结果汇总（LLM） | ≤ 2.0s |

#### 4.1.2 DeepResearch 完整研报响应时间

| 研究模式 | 目标值 | 说明 |
|---------|--------|------|
| quick_research | ≤ 30s | 快速研究 |
| research_sync | ≤ 120s | 同步深度研究 |
| research_stream | 首 token ≤ 5s | 流式研究，关注首 token 延迟 |

### 4.2 计算成本

#### 4.2.1 Token 统计

| 指标 | 测量方式 | 目标值 |
|------|---------|--------|
| 普通提问平均 input tokens | 统计三轮编排的总 input | ≤ 3,000 tokens |
| 普通提问平均 output tokens | 统计三轮编排的总 output | ≤ 1,500 tokens |
| DeepResearch 平均 input tokens | 统计完整研究流程 | ≤ 50,000 tokens |
| DeepResearch 平均 output tokens | 统计完整研究流程 | ≤ 10,000 tokens |

#### 4.2.2 成本换算

基于 qwen-max 定价：

| 场景 | 预估成本/次 | 计算方式 |
|------|-----------|---------|
| 普通提问 | ≤ ¥0.05 | (input × 输入价 + output × 输出价) |
| DeepResearch | ≤ ¥1.00 | 含多 Agent 协作的总 token 成本 |

### 4.3 并发处理

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| 最大并发用户数 | ≥ 10 | 压力测试 |
| 并发下 P95 延迟 | ≤ 普通延迟 × 2 | 10 并发下测量 |
| 错误率（并发） | ≤ 1% | 并发请求的失败比例 |
| MCP Server 稳定性 | 无崩溃 | 连续 1 小时压力测试 |

### 4.4 性能评估汇总

| 维度 | 核心指标 | 目标值 |
|------|---------|--------|
| 响应速度 | 普通提问 P95 | ≤ 8s |
| 响应速度 | DeepResearch 同步 | ≤ 120s |
| 计算成本 | 普通提问 token | ≤ 4,500 tokens/次 |
| 计算成本 | DeepResearch token | ≤ 60,000 tokens/次 |
| 并发 | 最大并发 | ≥ 10 |
| 并发 | 并发错误率 | ≤ 1% |

### B. FinResearchBench 参考

逻辑树评估方法参考 FinResearchBench 框架，适配本项目的 DeepResearch 多 Agent 架构：

- **Architect Agent** → 生成逻辑树根节点和一级分支
- **Scout Agent** → 扩展叶子节点（信息检索）
- **Wizard Agent** → 加深节点深度（分析推理）
- **Critic Agent** → 修剪低质量节点
- **Writer Agent** → 将逻辑树转化为研报文本

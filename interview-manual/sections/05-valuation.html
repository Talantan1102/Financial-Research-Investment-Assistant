05多模型估值与对抗

这一组题围绕 AlphaScout 在出投资尽调报告时,如何用「多个估值模型互相印证」和「多空两方吵架」两套机制把大模型最容易犯的两类错——数字瞎编、叙事一面之词——分别堵住。前两题铺底:为什么不止跑一个估值模型、模型按什么挑;后三题深入对抗辩论的结构设计、两层防御如何分工、多维裁判怎么搭、以及某个模型给出离谱数字时系统怎么不被带偏。答这组题,关键是说清「确定性数字交给 Python 算、判断交给大模型局部介入」这条贯穿主线,以及每个机制各自防的是哪一类幻觉。

Q1

做估值你为什么用 4 个模型 cross-check 而不是 1 个模型跑?那个按行业选模型的路由器是按什么选的?

★★★☆☆
交叉验证行业路由器确定性 vs LLM估值防幻觉

🎯 考察点分析

这道题表面问"几个模型",真正探的是两件事:第一,你懂不懂"让大模型自己拍一个估值数字"为什么危险——估值是个有严肃方法论的活,模型张口就来的"合理价"很可能是编出来的(幻觉),而没有任何机制去挑战它。第二,你做的"多模型"是不是真懂行——如果只是把同一类信号的模型堆四个,那叫互相附和,不叫验证。面试官想看你能不能把"为什么是 4 个、为什么还要按行业挑、挑的依据是什么"这条逻辑链讲透。

  • 追问:四个模型分别看公司的哪个侧面?为什么茅台和银行该用不同的模型?(考你懂不懂每个估值法背后"代理的是什么")
  • 追问:既然有四个,为什么不每家公司都把四个全跑一遍,取个平均不是更稳?(考你懂不懂"相关模型一起跑等于回声,不是验证")
  • 追问:那个按行业选模型的路由器,是写死的规则表还是让大模型来判断?为什么这么设计?(考你确定性与判断的边界划在哪)
  • 追问:遇到腾讯、美团这种"跨好几个行业"的公司,查表查不准怎么办?(考你有没有给规则表留判断的活口)

📚 原理讲解

先把最核心的一句话说清楚:所有估值方法,本质都是在回答同一个问题——"这家公司未来能产生多少现金"——只是从不同角度间接去估它。没有哪个方法能直接量出答案,它们都是代理(proxy):用一个能算的量,去近似那个算不出的真相。

四个模型 = 四把照不同侧面的尺子

项目里用的四把尺子是:

市盈率(PE)——用"今年赚多少利润"来代理。它假设今年的盈利能力大体能延续,适合盈利稳定、增长平滑的公司。
市净率(PB)——用"账上有多少净资产"来代理。适合资产本身就是生意核心的公司,比如银行,它的"家底"基本就是放出去的贷款。
企业价值倍数(EV-EBITDA)——用"剥掉利息、税、折旧之前的经营性赚钱能力"来代理。它特意把"借了多少债、设备折旧怎么算"这些会计差异抹掉,适合重资产、负债结构差异大的公司(钢铁、电信)。
现金流折现(DCF)——不绕弯子,直接预测公司未来十年每年产生多少自由现金,再折算回今天值多少钱。它最接近"未来现金"这个真相,但也最依赖假设(增长率、折现率),错一点假设结果差很远。

关键洞察:同一个真相,四把尺子从四个独立角度去量,如果几把尺子量出来的数字彼此接近,这个"接近"本身就是强信号——说明这个估值不是某一种方法的偶然产物。反过来,如果只用一把尺子,你永远不知道它量歪了没有,因为没有第二个独立来源能拆穿它。这就是 cross-check(交叉验证) 防幻觉的核心:让一个模型自己说"合理价是 X",没人能反驳;让四个独立方法各自算,一致性就成了可被检验的事实。

为什么不四个全跑?——回声不是验证

这是最容易被忽略、也最能体现专业度的一点。真正的研究员很少把四个模型每家都跑一遍,原因是:对某些公司,某几把尺子量的其实是同一个东西。比如茅台这种利润稳、几乎没什么债的公司,它的 PE 和 EV-EBITDA 高度相关——两个数字会一起涨一起跌。这时候同时跑这两个,得到的"两个一致结果"是假的安全感:它们一致不是因为彼此独立印证,而是因为它们本来就是一回事在重复(echo)。验证的前提是"独立",回声破坏了这个前提。

所以正确做法是:每个行业只激活那几把"真能照出新信息"的尺子,通常 2 到 3 把。这既保证了"多个独立视角"的防幻觉效果,又避免了用相关模型互相附和制造的虚假一致。决定"该激活哪几把"的,就是那个按行业选模型的路由器。

行业路由器:为什么是"查表为主、判断为辅"的两层结构

路由器叫 IndustryModelRouter(行业模型路由器),核心结构是两层混合:

第一层是一张写死的查找表(行业 → 该用哪几把尺子)。比如白酒/食品饮料 → PE + DCF(盈利稳、看长期现金);银行 → PB + EV-EBITDA(看家底);钢铁/煤炭 → EV-EBITDA + PB(重资产、负债重);查不到的行业 → 退回安全默认 PE + DCF(两把相对独立的尺子兜底)。这张表覆盖大约 80% 的标准行业(量级估计),它的好处是确定、零成本、可测试——同一个行业每次都得到同样的答案,不花一次大模型的钱,写单元测试一测一个准。

第二层是一个可选的"大模型判断"活口。问题在于:腾讯算科技还是金融还是消费?美团算消费还是平台?这种跨界公司,写死的表根本对不上号。所以留了第二层——让大模型在分析公司业务时,如果发现"这家不属于任何标准行业",可以覆盖(override)第一层的默认选择。但这个判断不是黑箱:它必须给出一段不超过 200 字的理由(作为可追溯的审计记录),还要标一个置信度(高/中/低)——高代表强信号,低代表"也就拍个脑袋"。需要说明的是,当前这一期里,第二层的接口已经搭好,但分析模块默认不去调它(覆盖值固定为空),只是留了个挂钩给后续真正接入。

这两层的分工,正好对应整个估值系统贯穿始终的一条主线:"数字用确定性的 Python 算,判断才交给大模型,而且只在有据可依的局部"。查表是确定性骨架,大模型只在"标准规则照顾不到的边界"上做局部判断——这恰好复刻了真实研究员"七分判断、三分规则"的工作方式,而不是把估值整个外包给一个会编数字的模型。

💻 示例讲解

用一段教学伪代码走一遍路由器两层的逻辑。注意看:第一层永远先跑(确定、免费),第二层只是个"可选的覆盖",当前默认不触发。

# ===== 行业模型路由器:先查表,再(可选地)让模型覆盖 =====

# 第一层:写死的行业 → 激活模型 查找表(覆盖约 80% 标准行业)
行业到模型映射 = {
    "白酒":   ["PE", "DCF"],          # 盈利稳,看长期现金
    "银行":   ["PB", "EV-EBITDA"],    # 资产即生意,看家底
    "钢铁":   ["EV-EBITDA", "PB"],    # 重资产、负债重
    "_default": ["PE", "DCF"],        # 查不到 → 两把独立尺子兜底
}

def 查表选模型(行业分类):
    # 命中就用该行业的,没命中退回安全默认值
    return 行业到模型映射.get(行业分类, 行业到模型映射["_default"])

def 应用模型覆盖(默认模型, 覆盖):
    # 覆盖为空(本期默认)→ 直接用查表结果,不动它
    if 覆盖 is None:
        return 默认模型, None
    # 覆盖非空(跨界公司,后续接入)→ 用模型的判断,
    # 并连同它给的理由(≤200 字)一起返回,留作审计记录
    return 覆盖.覆盖模型, 覆盖.理由

# ---- 主流程 ----
默认 = 查表选模型("白酒")                  # → ["PE", "DCF"]
激活模型, 理由 = 应用模型覆盖(默认, 覆盖=None)  # → ["PE", "DCF"], None
# 注意:激活的是 2 把,不是 4 把全跑 —— 只挑信号密度高的

推演:输入一家白酒公司,第一层查表直接命中,激活 PE + DCF 两把尺子;第二层覆盖为空(本期默认),不动它。最终只跑这 2 个独立模型做交叉验证——而不是把 PE/PB/EV-EBITDA/DCF 四个全跑。假如硬要四个全跑,PE 和 EV-EBITDA 对茅台这类公司高度相关,得到的"两者一致"是回声不是验证,白白多花算力还制造虚假的安全感。换成腾讯这种跨界公司,查表查不准,后续接入后第二层就会触发:大模型判断"它兼具科技+金融+消费",覆盖默认选择,并附一段不超过 200 字的理由 + 置信度,方便事后复盘它判得对不对。

📌 总结

  • 四个模型(PE/PB/EV-EBITDA/DCF)是同一个问题"公司未来能产生多少现金"的四个独立代理:用多把独立尺子交叉验证,是为了防止大模型自己编一个"合理价"却无人能挑战——一致性本身就是可被检验的信号。
  • 不四个全跑:对某些公司,某几把尺子是相关的(茅台的 PE 与 EV-EBITDA),一起跑只是回声不是验证;所以每行业只激活"真有信号密度"的 2-3 把。
  • 选哪几把由行业模型路由器(IndustryModelRouter)决定:第一层写死查找表(白酒→PE+DCF、银行→PB+EV-EBITDA、未命中→PE+DCF),确定/免费/可测,覆盖约 80% 标准行业(量级估计)。
  • 第二层是可选的大模型覆盖,给腾讯/美团这种跨界公司用,带 ≤200 字理由 + 置信度(高/中/低)做审计;本期接口已就位但默认不触发,留作后续接入的挂钩。
  • 贯穿主线:数字用确定性 Python 算,判断才交给大模型且只在有据可依的局部——复刻研究员"七分判断、三分规则"的工作流,而不是把估值整个外包给会编数字的模型。下一步这 2-3 个数字怎么判一致,见本类第 3 题;某个模型给出离谱值怎么诊断,见本类第 5 题。

一句话速记:四把独立尺子交叉验证防"模型编数字",行业路由器先查表(确定)、跨界才让模型覆盖(带理由),只激活 2-3 把信号尺、避开相关模型互相回声。

Q2

多空两轮对抗辩论是怎么用「对抗」这个结构来防幻觉的?为什么要两轮?

★★★★☆
对抗辩论多智能体叙事幻觉两轮反驳确认偏误

🎯 考察点分析

面试官在探的是:你是不是真的理解「大模型为什么会胡说」分两种,以及「对抗」这个结构到底解决了哪一种。很多人一听「防幻觉」就答检索增强、答让另一个模型核对事实——那是防「数字编错」。但这道题问的是另一半:报告里每个数字都对、却只讲了一面之词,这种「叙事幻觉」靠核对事实根本抓不到。能不能把这两种幻觉拆清楚,是这题的分水岭。

第二层在探「为什么是两轮」。这是个很容易暴露深浅的追问:一轮也能让多空两方各说一遍,凭什么非要第二轮?如果你答不出「第一轮各说各话本质不是辩论、第二轮才有真反驳」,就说明你只是照搬了 multi-agent debate 的框架,没想清楚每一步的产出差异。

  • 追问:让一个模型自己同时写多空两面,不也能覆盖正反吗?为什么非要两个独立的 agent?
  • 追问:第二轮多花了一倍的钱和延迟,这笔账你怎么算的?为什么不做三轮、四轮直到双方收敛?
  • 追问:两个 agent 要并行跑,它们引用的估值数字怎么保证一致?会不会各自又去拉一遍数据导致两人吵的根本不是同一个事实?

📚 原理讲解

先把幻觉拆成两种。第一种是事实编错——把市盈率说成 40 倍实际是 20 倍,这种有专门的「裁判」逐条核对事实正确性,能抓住(那是本类第 1 题 cross-check 和第 4 题裁判的活儿)。第二种是叙事幻觉,也叫一面之词:每个数字都对,但报告只挑了支持「该买入」结论的证据,该提的风险一句没提。这第二种,核对事实的裁判抓不到——因为它只验「说的对不对」,不验「说的全不全」。

为什么单个模型天然会一面之词

大模型有个根深蒂固的毛病叫确认偏误:它一旦在脑子里先倾向了某个结论,后面找证据就会自动往那个方向找,不会主动去翻反方的料。让一个 Writer 一口气写完整篇报告,它就会顺着自己最先形成的判断一路写下去,正反两面看起来都提了,其实反方那几句是敷衍的「凑数论据」。更糟的是,即便你让同一个模型「自己也写写空方观点」,它写出来的空方往往和多方是同一个脑子产的、同质化——左手打右手,使不上劲。

「对抗」这个结构怎么破局

办法是把正反两方拆成两个独立的 agent:一个看多辩手、一个看空辩手,各自被提示词灌「30% 看多 / 30% 看空」的立场(不是 100%,留出讲道理的余地,不变成无脑吹/无脑黑)。两个独立的脑子,各自被要求只为自己这一方找最有力的论据,每条必须引用具体数字或事实。这就强制制造了两个真正不同的视角,破掉了单模型的同质化。这套路子学术上叫 multi-agent debate(多智能体辩论),源头是 2018 年「靠辩论实现 AI 安全」的思路,后来 AutoGen、MetaGPT 这些框架把它做成了通用范式。

为什么必须两轮——一轮不是辩论

这是全题的题眼。第一轮,两个辩手背对背、看不到对方,各自独立陈述——多方列多方的料,空方列空方的料,「反驳了对方哪几条」这个字段是空的。这一轮本质是两份独立的单面报告并排放,根本没有交锋。

第二轮才是真对抗:把对方第一轮的论据原文喂给你,你看完之后产出第二版,并且要标注「我反驳了对方哪几条」(引用对方论据的原文片段)。只有到了这一轮,多方的第二版才是真的在拆空方第一版的软肋,叙事质量是升级而不是两份独立报告求平均。一轮只能拿到「各说各话」,两轮才能拿到「针锋相对」,这是结构上的质变,不是数量上多跑一遍。

每个辩手还自带一个元认知信号:除了 3-5 条论据,要自评一条「最强论据」(≤300 字)和一个自信度(高/中/低)。这逼着模型把「凑数的料」和「真有杀伤力的料」分开,防止论据被稀释成一堆废话。这跟第 1 题里异常值诊断 agent 自报置信度是同一个套路。

# 两个辩手都从同一份「共享估值数字」里取数,各自不重新拉数据
# 这样两人吵的是同一个事实地基,而不是各拉各的数互相错位
shared = state.valuation_analysis   # 第 1 题 cross-check 算好的 PE / DCF 三档

# ---- 第 1 轮:背对背,各自独立陈述 ----
# 两个辩手并行跑(asyncio.gather),总耗时 ≈ 一个辩手的延迟
bull_v1, bear_v1 = await gather(
    to_thread(bull.advocate_round_1, state),   # 看多方:只列多头论据
    to_thread(bear.advocate_round_1, state),   # 看空方:只列空头论据
)
# 此刻两份都是「单面陈述」,rebut_targets(反驳了哪几条)还是空的

# 有一边没产出 → 不强行单方辩论,优雅降级回单线报告
if bull_v1 is None and bear_v1 is None:
    return None                # 两边都挂,直接走原来的单 Writer 路径

# ---- 第 2 轮:交叉喂对方第一版,这才是真对抗 ----
bull_v2, bear_v2 = await gather(
    to_thread(bull.advocate_round_2, state, bear_v1),  # 多方读空方 v1 → 产 v2 + 标反驳
    to_thread(bear.advocate_round_2, state, bull_v1),  # 空方读多方 v1 → 产 v2 + 标反驳
)

# 第 2 轮任一边失败 → 整体退回第 1 轮的结果(rounds_completed=1)
# 宁可退到「各说各话」,也不给一份「单方挨打」的不对称辩论
if bull_v2 is None or bear_v2 is None:
    return DebateTrace(..., rounds_completed=1)

return DebateTrace(bull_v1, bear_v1, bull_v2, bear_v2, rounds_completed=2)
# 两版多空全部交给 Writer 综合成最终报告(强制正反都引用)

推演:2 轮 × 2 辩手 = 4 次大模型调用。辩手走便宜的 fast 档,单次约 $0.0008,整套 debate 增量约 $0.0032(4 个辩手 × fast 档)——相对原来单 Writer 一次调用(balanced 档约 $0.005),总成本约 1.6 倍,完全可控。每个辩手列 3-5 条论据、最强论据 ≤300 字、反驳条目 ≤5 条,这些上限都写在 schema 里硬卡死,防止模型自评滥用。整个对抗辩论这个特性的代码量约 1100 行 / 8 次提交。

Q3

你说的「双重幻觉防御」完整闭环是什么?cross-check 和对抗辩论各防住了哪一半?

★★★★☆
双重防御防幻觉数字 vs 叙事完整闭环架构

🎯 考察点分析

这道题面试官表面问"两层防御都防什么",真正想看的是你能不能讲清一件事:大模型会犯的错不止一种,而且这几种错是正交的——堵住其中一种,另一种照样漏。会做防御的人,先得能把"幻觉"这个笼统的词拆成两类形状完全不同的错误,再说清每一层各对应哪一类。如果你只会说"多算几遍更准",那说明你没想清楚这两层为什么不能合成一层、也不能只留一层。这是个考"防御体系完整性"的题,不是考"哪个算法更牛"。

  • 追问:这两层防的是同一种错的轻重程度,还是两种本质不同的错?你凭什么说它们正交?
  • 追问:假设数字层判定"四个估值方法高度一致",报告还可能有幻觉吗?举个具体例子。
  • 追问:这两层有先后顺序吗?能不能反过来先做辩论再做数字 cross-check?
  • 追问:你怎么保证这两层不是"摆设"——光写了代码但生产环境根本没接上、报告照样放行?

📚 原理讲解

先把"幻觉"这个词拆开。在一份投资尽调报告里,大模型容易犯的错其实是两类形状完全不同的错,我把它们分别叫"数字幻觉"和"叙事幻觉"。

第一类:数字幻觉——估值数字脱离方法被拍出来

你让大模型给一家公司估个值,它可能直接"拍"一个看着合理的目标价出来,而这个数字背后并没有一套站得住的算法支撑——它是被语言模型按"语感"生成的,不是算出来的。这类错的特征是:单看一个数字你看不出问题,要把几个独立的估值方法摆在一起才暴露。所以第一层防御叫 cross-check(交叉验证):同时跑市盈率、市净率、企业价值倍数、现金流折现四套独立方法,再做一致性判定——如果四个数算出来彼此打架(比如一个说该涨 50%、一个说该跌 30%),系统就知道有数字不可信,触发异常诊断把那个离谱的方法揪出来。哪个方法离谱、为什么离谱,见本类第 5 题。

第二类:叙事幻觉——一面之词,只说看多不说看空

第二类错跟数字一点关系都没有。哪怕四个估值数字高度一致、完全可信,大模型在写文字论证那一段仍然有个天生的毛病,叫"确认偏误":它倾向于只去找支持自己已有倾向的证据,而不主动列举反方证据。用茅台举例——它会大写"品牌护城河三十年、净资产收益率三十年稳定在 30%",却绝口不提"年轻一代不喝白酒、渠道库存高、反腐影响"。这种单线叙事才是真正的尽调失败:基金经理拿到一份只说好不说坏的报告是不敢按它下单的,他必须看到"反方观点已经被严肃考虑过"。所以第二层防御是 bull/bear 对抗辩论:让两个大模型分别被灌"坚定看多"和"坚定看空"的立场,各自找论据、互相反驳两轮,最后由写手综合成一份双向的报告。为什么非要两轮、对抗这个结构本身怎么防幻觉,见本类第 2 题。

关键洞见:两类错正交,所以非两层不可

这是整道题的题眼:数字对不对和叙事全不全是两个互相独立的问题。即使数字层判定四个方法高度一致,叙事仍然可能是一面之词;即使叙事做到了双向,某一个估值方法的数字仍然可能离谱。两个问题不相干,任何单独一层都注定漏掉另一半。更要命的是,这个漏洞连裁判都抓不住——我们的裁判(Critic)有一个维度叫"事实性",但它只验"写出来的事实对不对",不验"事实全不全面"。所以一份"事实条条正确、却只说看多"的报告,会在事实性那一关拿满分顺利放行。要堵住这个洞,必须额外加一个专门评"双向程度"的维度。

两层有先后:数字层是叙事层的弹药库

这两层不是平行的,有依赖顺序。先夯数字层,辩论才有真实弹药:看多方和看空方吵架时不能凭空编数字,他们引用的正是数字层算出来的现金流折现乐观情景、悲观情景、估值数据和异常诊断结论。辩论本身不重新算任何数字,它站在数字层之上。所以数字层可以独立上线、独立有价值;而辩论层必须等数字层先就位。正因如此,我们把它拆成两个 PR 按顺序交付——数字先、叙事后——而不是攒成一个大 PR,这个取舍下面决策对比里展开。

💻 示例讲解

用一段伪代码把"完整闭环"走一遍。注意两层各自带一个裁判维度、各自带一条重写回环,而辩论层引用的全是数字层的产出。

# ===== 第一层:数字层 cross-check(防数字幻觉)=====
# 四套独立方法各算一遍,数字全用确定性代码算,不让模型"拍"
valuations = {
    "市盈率":    pe_value(...),
    "市净率":    pb_value(...),
    "企业价值倍数": ev_ebitda_value(...),
    "现金流折现": dcf_value(...),   # 含乐观/中性/悲观三情景
}
# 一致性判定:四个数彼此打不打架?
consistency = check_consistency(valuations)        # 算出一致性分
outlier = diagnose_outlier(valuations)             # 揪出离谱方法 + 给原因

# ===== 第二层:叙事层对抗辩论(防叙事幻觉)=====
# 关键:辩论不重算数字,它「引用」数字层的产出当弹药
bull = bull_advocate(dcf_bull=valuations["现金流折现"].乐观,    # 看多方引乐观情景
                     outlier=outlier)
bear = bear_advocate(dcf_bear=valuations["现金流折现"].悲观,    # 看空方引悲观情景
                     pe=valuations["市盈率"],
                     outlier_narrative=outlier.叙事,
                     consistency=consistency)                  # 看空方还引一致性结论
# 两轮互相反驳后,写手综合成一份「既有看多章、也有看空章」的报告
report = writer_synthesize(bull, bear, valuations)

# ===== 两层各自的裁判维 + 重写回环 =====
scores = critic_score(report)        # 裁判一共 8 个维度打分
# 第 7 维:数字一致性(数字层守护) / 第 8 维:辩证平衡(叙事层守护)
if scores["数字一致性"] < 7.0 or scores["辩证平衡"] < 7.0:
    report = writer_retry(report)    # 任一维不及格 → 打回重写

推演:设想茅台这份报告。数字层四套方法算下来高度一致、没有离谱方法,第 7 维"数字一致性"打 9 分——数字这一半干干净净。但写手在叙事里只堆了护城河和高净资产收益率,一句利空没提。如果只有数字层,这份报告会被放行——因为事实性那关它条条属实。第 8 维"辩证平衡"专门数这件事:看空论据少于两条就判低分,于是它打 3 分,低于 7.0 这条线,报告被打回重写,逼写手把库存、消费降级、政策这些反方证据补进去。两层各管一半:数字层管"四个方法 4 个 LLM 调用之外的确定性算账",叙事层走两轮、每轮看多看空各一次共 4 次模型调用把反方意见硬塞进来。缺任何一层,这份报告都会带着另一半的幻觉溜出去。

Q4

你的裁判(Critic)有 7 到 8 个维度,这些维度怎么设计的?后来加的第 8 维加的是什么?

★★★★☆
多维裁判rubric 评分规则裁判重试闭环死代码教训

🎯 考察点分析

这道题问的是「怎么自动判一份报告写得好不好」。面试官表面在数维度,真正想确认三件事:你是把质量当成「一个总分」拍脑袋,还是把它拆成几条互不重叠的标尺分别量;你知不知道什么质量轴该用大模型判、什么轴用规则判更靠谱;以及加一个新维度时,你有没有把它真正接进生产、接进重试回路,而不是写完就躺在那里没人调。

  • 追问:同样是「事实层面」的检查,你已经有一个「事实是否正确」的维度了,为什么还要单独加一个「是否一面之词」的维度?它们差在哪?
  • 追问:第 7、8 维你说不调大模型、用规则算分。一个验数字、一个验叙事,凭什么规则就够了?换大模型当裁判不更聪明吗?
  • 追问:裁判给了低分之后呢?分数只是打印出来给人看,还是真能驱动系统自己去改?
  • 追问:你提到「死代码教训」,新维度写完到真正生效,中间漏一步会怎样?你怎么防?

📚 原理讲解

先说背景。报告写完之后要有人验收。最省事的做法是让一个大模型读完报告、打一个「综合分 7.5」。问题是综合分像一锅乱炖——你只知道这份报告「整体一般」,但不知道差在事实、差在覆盖、还是差在结构。低分定位不到病根,就没法对症下药。

多维评分:一条标尺只量一个质量轴

所以裁判被拆成多个正交的维度,每个维度只盯一类缺陷,互不串味。基线是 6 条,全部由大模型来判:事实是否正确、覆盖是否完整、有没有洞察、结构清不清楚、是否简洁、以及「有没有用好喂给它的上下文」。每条独立打分,哪条低分就精确指向哪类毛病。

这里有个关键设计动机,正好回应面试官的追问:为什么「事实正确」之外还要单开一维?因为「事实正确」只验你写的每句话是不是真的,它验不出你说的是不是全面。一份只讲利好、把所有利空都藏起来的报告,可以做到句句属实——每个事实都对,但整体是一面之词。这种「正确但片面」是单条事实维度的盲区,必须靠一条专门的「是否双向论证」的维度去兜。这就是后来加的第 8 维。

第 7、8 维:不调大模型,用规则算分

项目演进里又补了两维,而且这两维很特殊——它们不调大模型,用确定性规则直接算分。

第 7 维是「估值一致性」,来自多模型交叉验证那条线(见本类第 1 题)。第 8 维是「辩证平衡」,来自多空两轮对抗辩论那条线(见本类第 2、3 题)。为什么这两维敢用规则?因为它们要验的不是「文笔好不好」这种主观的东西,而是一件很具体的事:报告的叙述,有没有把 Python 算出来的那些确定性信号如实反映出来。第 7 维管「数字层」——几个模型估出来的价打不打架,报告有没有承认;第 8 维管「叙事层」——多空双方各自摆出的论据,报告有没有真的两边都引用。

这种「叙述 vs 确定性信号」的对照,用规则(子串匹配、关键词命中)就能表达干净。对比让大模型当裁判,规则有三个硬优势:可测(同样的输入永远同样的分,能写单元测试逐档锁死);零成本(不烧 token、不等网络);可复现(评测结果不会因为模型今天心情不同而漂)。两维都预留了大模型注入接口,将来真要换成模型裁判,可以换实现而不破坏对外契约。

低分要能驱动重写:重试闭环

裁判不是终点。第 7、8 维都接进了「写手重试」回路:任意一维分数低于 7.0,就把当前的重试路由触发,让写手拿着裁判的具体反馈再写一遍。这个回路最早是「事实」维度建好的,后来两个新维度直接复用同一条边——现在这条重试路由一共盯三个触发器:事实、估值一致性、辩证平衡。任意一个塌了就回炉。

最后一个工程教训值得专门讲:这个项目早先吃过「死代码」的亏——评分器类写好了、单元测试也过了,但忘了把它注册进生产用的评分器清单、忘了在裁判的并行扇出里加上它,结果生产里这一维零调用,等于没写。所以第 7、8 维上线时都强制补三件套:注册进生产清单、加进裁判扇出、再加一个集成测试专门守着「它真的被调到了」。

💻 示例讲解

看第 8 维「辩证平衡」的规则怎么算分。核心就一句话:从辩论记录里取双方的最终论据,数一数各有几条作为子串出现在报告正文里,然后按命中数分档。

# 第 8 维:辩证平衡 —— 报告有没有真的两边都讲(规则裁判,不调大模型)
def 评辩证平衡(辩论记录, 报告正文):
    # 1) 取「最终一轮」的论据:打满两轮就取第二轮,只打了一轮就取第一轮
    if 辩论记录 is None or 辩论记录.完成轮数 == 0:
        return 10.0  # 没辩论 / 双方都失败 → 标记跳过,不拉低总分

    取哪轮 = 2 if 辩论记录.完成轮数 == 2 else 1
    看多论据 = 辩论记录.取看多论据(取哪轮)   # 一串文本,每条是一个论点
    看空论据 = 辩论记录.取看空论据(取哪轮)

    # 2) 数「有几条论据原文出现在报告正文里」(子串命中)
    看多命中 = sum(1 for 论点 in 看多论据 if 论点 in 报告正文)
    看空命中 = sum(1 for 论点 in 看空论据 if 论点 in 报告正文)

    # 3) 按命中数分档 —— 阈值 7.0 是重试线
    if 看多命中 >= 2 and 看空命中 >= 2:
        return 9.0   # 真双向:多空各引 2 条以上
    if 看多命中 >= 2 or 看空命中 >= 2:
        return 3.0   # 掩盖一面:只引了一边 → 低于 7.0,触发重写
    if 看多命中 == 1 and 看空命中 == 1:
        return 6.0   # 论据稀薄:各 1 条 → 低于 7.0,触发重写
    return 4.0       # 几乎不引用辩论 → 低于 7.0,触发重写

推演:假设辩论打满两轮,取第二轮论据,看多 3 条、看空 3 条。报告里看多论据命中了 3 条,但看空论据一条都没写进去(命中 0)。走到第二个分支(一边 ≥2、另一边 <2),判 3.0,证据记成「掩盖看空」。3.0 远低于 7.0,重试路由立刻把写手拉回来,带着「你只讲了利好、把利空全藏了」的反馈重写一遍。反过来,如果改写后多空各命中 2 条以上,这一维升到 9.0,放行。注意「没辩论」的情形给的是 10.0 并标记跳过——它不算在总分里,避免「没跑辩论」反而被当成满分拉高了整体。

Q5

DCF 三种情景 + 异常值诊断 agent:某个模型给出一个离谱的估值,系统怎么诊断、怎么不被它带偏?

★★★★☆
DCF 三情景异常值诊断变异系数 CV大模型当诊断师不取平均

🎯 考察点分析

面试官想确认两件事。第一,你懂不懂「几个模型一起算估值,结果打架了怎么办」这个真问题——新手的本能是把它们平均一下,但这恰恰是错的。第二,你能不能把「大模型」放在一个克制的位置上:不是让它拍脑袋出最终估值,而是让它干一件人类研究员真会干的事——回去查到底哪个假设错了。这道题考的是「你信不信数据本身在说话」,以及「你愿不愿意把贵的大模型只用在刀刃上」。

  • 追问:四个模型里有一个估值离谱地高,你直接取平均会怎样?为什么不行?
  • 追问:你怎么判定「打架」到什么程度才算严重?这个阈值是大模型判的还是写死的?
  • 追问:诊断完了,系统会不会自己拿那个离谱值去重算?为什么不?
  • 追问:万一写报告的环节把「打架」这件事悄悄抹平了,你怎么兜住?

📚 原理讲解

先把场景说清楚。给一家公司估值,我们同时跑四把「尺子」:市盈率、市净率、企业价值倍数、还有现金流折现(DCF)。四把尺子各给一个理论价。它们大致接近,我们就放心;某一把给出一个离谱的数,问题来了——这是哪把尺子坏了,还是它看见了别人没看见的东西?

DCF 的三种情景:不是一个数,是一束数

DCF 不吐一个点估值,而是吐三个并列的理论价:中性(base)、乐观(bull)、悲观(bear)。这三个数是独立存下来的,系统不对它们做任何概率加权或混合——其中只有中性价进入和其他模型的跨模型一致性比较,乐观/悲观两个数只供敏感度参考,看清「假设乐观一点或悲观一点,结论会差多少」。三者的差别全在「未来十年增长率怎么走」这条曲线上:程序先生成一条从启动增速、十年线性衰减到「行业永续增速」的序列。中性场景的启动增速优先用管理层自己的业绩预告,没有就用历史均值;乐观/悲观则是把启动点相对永续增速的偏离量放大或缩小(乘 1.2 / 0.8),这样无论公司是正增长还是负增长,都能保证乐观高于中性、中性高于悲观。

关键的一条边界:折现率(WACC)和永续增速这两个参数不让大模型碰,完全由 Python 按金融学公式确定地算(比如个股风险 β 偏离市场每一个单位调 ±2%、负债过高再加 1% 风险溢价)。再配一张 5×5 敏感度表(折现率上下浮动 1%/2% × 永续增速上下浮动 0.5%/1%),让人看清结论对假设有多敏感。一句话:DCF 这一束数是确定性算出来的,大模型只在「有信息源支撑的判断」(中性场景的增长率取管理层预告)上局部插手。

用变异系数量化「打架」

四把尺子的数收齐后,先算它们的「离散程度」——变异系数 CV = 标准差 / 均值(用 n−1 的样本标准差,对齐金融学口径)。算之前先剔掉 0、负数、无穷、非数这些脏值,有效数字不足两个或均值为零就直接返回「无信号」。CV 分三档:小于 15% 算一致、15%–30% 算中度分歧、大于 30% 算严重分歧。这是个纯算术判定,没有大模型参与——阈值是写死的,可解释、可复现。

严重分歧不是 bug,是 signal

这是整道题的题眼。当 CV 超过 30%,系统的态度不是「出错了,重试」,也不是「取个平均糊弄过去」,而是把它当成一个信号:某把尺子在告诉你一件别的尺子没看见的事。于是系统启动一个专门的「异常值诊断 agent」,复刻真实研究员的动作:回去查——四把尺子里哪一把最偏离共识?它的关键假设错在哪?我有多大把握?该怎么处理?这个 agent 只在严重分歧时才触发(一致/中度都不调,省成本),走中等档位的模型,输出是结构化约束的:离群的是哪把尺子、可能的原因(≤300 字)、信心(高/中/低)、建议动作、以及一段给用户看的大白话叙述(≤500 字)。大模型在这里是「诊断师」,不是判官、也不是写手——它不改最终估值,只给出「哪里可能错了」的解释。

不被带偏的四道闭环

(1) 诊断只标出离群的那把尺子,绝不把它和别的平均;(2) 建议动作默认是「信其余几把尺子」或「把不确定性 flag 给用户」,绝不让系统自动拿那个离谱值去重算(「调整假设重算」这个选项留到将来,现在不实施,避免拿假数据自我循环);(3) 诊断本身失败了,就返回「无诊断」且不重试,叙述里直接 flag「无法诊断打架原因,请人工 review」;(4) 最后还有一道裁判:写报告时如果有诊断,正文必须真的引用那段叙述,裁判的「估值一致性」维度会校验——引了给 9 分、没引只给 3 分,低于 7 分就把报告打回重写,专门防写手把打架信号悄悄抹平。

💻 示例讲解

下面这段伪代码把整条流水线串起来:从四把尺子的数字,到 CV 判档,再到「只在严重时」叫诊断师。注意诊断师失败时的兜底,以及「绝不取平均」这条线。

# 四把尺子各算一个理论价(DCF 这一栏其实是 base 场景)
估值 = {"市盈率": 1500, "市净率": 1550, "企业价值倍数": 1480, "现金流折现": 4200}

def 判定分歧(估值字典):
    # 先剔掉脏值:零、负数、无穷、非数,都不进统计
    有效 = [v for v in 估值字典.values() if v > 0 and 是有限数(v)]
    if len(有效) < 2:
        return None                      # 不足两个 → 没有 cross-check 信号
    均值 = sum(有效) / len(有效)
    # 变异系数 = 样本标准差 / 均值(n-1 口径)
    cv = 样本标准差(有效) / 均值
    if cv < 0.15:  return "一致"          # 绿:放心
    if cv < 0.30:  return "中度分歧"      # 黄:叙述里要解释偏离
    return "严重分歧"                      # 红:这才是信号

分歧档 = 判定分歧(估值)

# 核心:严重分歧不取平均、不重试,而是叫诊断师回去查假设
if 分歧档 == "严重分歧":
    诊断 = 诊断师.诊断(估值, 各模型关键假设, 公司基本面)   # 走中等档位模型
    if 诊断 is None:
        # 诊断也失败了 → 不重试,叙述里 flag 给人工
        叙述 = "无法诊断打架原因,请人工 review"
    else:
        # 诊断师只标出离群的那把尺子,默认建议「信其余几把」
        叙述 = 诊断.narrative          # 写手必须原样引用这段
# 一致 / 中度分歧:压根不叫诊断师,省钱

推演:四个数 1500 / 1550 / 1480 / 4200,均值约 2182,样本标准差约 1335,CV ≈ 61% > 30% → 落进红区。对比一下「直接取平均」:把 4200 这个离谱值算进去,结论就是约 2182——硬生生被一把坏尺子拉高了一截,而且完全看不出曾经打过架。我们的做法是:不平均,叫诊断师查出「现金流折现这把尺子最偏离共识,很可能是它的增长率假设给得过于乐观」,信心中等,建议「信其余三把尺子(约 1510),并把这个分歧 flag 给用户」。最终结论锚在 1510 附近,而不是被 4200 污染到 2182。如果连诊断师都调用失败,就老实写「无法诊断,请人工 review」——绝不假装没事。

离谱值的影响显式标出离群尺子,默认信其余几把,结论不被污染离谱值直接进均值,把结论拉偏
对「打架」的态度当信号:回去查哪把尺子的假设错了当噪声:平均一下抹平,信息丢失
可解释性给出离群点 + 原因 + 信心 + 建议,报告里有据可讲只有一个平均数,讲不清为什么
成本只在严重分歧才叫大模型,一致/中度零额外调用取平均零成本,但没有诊断价值
失败兜底诊断失败 → flag 人工 review,不假装正常无诊断环节,无所谓兜底
防写手掩饰裁判校验正文是否真引用诊断,没引就打回重写无此机制

公允裁决:直接取平均不是稻草人——它简单、零成本、在四把尺子本就接近时(一致档)结论和我们几乎一样,这也是为什么我们在一致/中度档根本不调诊断师,行为上就退化成「信这几把尺子」。它真正的短板只在「有一把尺子离谱」时才暴露:平均会被污染,而且把「为什么打架」这条最有价值的信息直接丢了。我们另外还否掉过两个更复杂的方案:一是「事后让裁判+重写」兜底,但这是被动的——写手可能先把分歧模糊化,要重写一两轮才稳;二是「让数据采集层多抓点数据重算」,但根因不在数据缺失,假设没变、数据再抓也是同一个离谱值,白白拖慢。最终选「让大模型当诊断师」:它对应真研究员遇到模型打架时『回去查哪把尺子在告诉我没看见的事』的工作流,提供了算法层的可解释性,而且只在严重时触发。一条铁律贯穿始终:大模型只动有信息源支撑的假设(增长率的中性场景),绝不动金融学公式锚定的折现率和永续增速。

📌 总结

  • 四把尺子打架的程度用变异系数量化(标准差/均值,n−1 口径),三档:小于 15% 一致、15%–30% 中度、大于 30% 严重——纯算术、写死阈值、不调大模型。
  • 严重分歧「不是 bug,是 signal」:不取平均、不重试,而是叫专门的诊断师回去查哪把尺子的假设错了,复刻真研究员的工作流。
  • 大模型在这里只当「诊断师」:输出离群点 + 原因 + 信心 + 建议,且只在严重档触发(一致/中度零额外成本),绝不让它改最终估值或动公式锚定的折现率/永续增速。
  • 不被带偏靠四道闭环:标离群不平均 / 默认信其余几把不自动重算 / 诊断失败就 flag 人工 / 裁判校验报告是否真引用诊断,没引打回重写。
  • DCF 同理不是一个点,而是中性·乐观·悲观三束 + 5×5 敏感度表,全程确定性 Python,只有中性场景的增长率允许接管理层预告。双重幻觉防御的另一半见本类第 3 题。

一句话速记:模型打架不取平均——把它当信号,叫大模型当诊断师回去查哪把尺子的假设错了,默认信其余几把,还有裁判盯着报告不许把分歧抹平。
